### 6.2 CI 能否真的跑起来：**当前不能**（R2-QA-01）

```yaml
# ci-adapter.yml:106-112
- uses: astral-sh/setup-uv@v5
  with: { enable-cache: true, cache-dependency-glob: apps/adapter/uv.lock }
```

`astral-sh/setup-uv` 的官方 README 明确：该 action 只把 **`uv` 本身**加入 PATH，`activate-environment` **默认 `false`**（"Use uv venv to activate a venv ready to be used by later steps"，默认关）。`uv sync` 把依赖装进 `apps/adapter/.venv`，**不会**把 `.venv/Scripts|bin` 加进 PATH。因此 `ruff` / `mypy` / `pytest` 三条裸命令在 GitHub runner 上会 `command not found` → **整条适配层门禁在第 1 个 step 就红**，后面 20 余道门禁一步都跑不到。

## 九、测试体系成熟度结论

### 9.1 能抓住的回归（已由本轮变异测试实证）

1. **底座客户端生命周期 / 流式连接泄漏**（H-1）——删掉 `finally: aclose()` 立刻 2 红；
2. **幂等失效**（重复提交会重复扣费/重复建单）——`get()` 恒 None 立刻 4 红；
3. **令牌过期校验被摘掉**——`verify_exp=False` 立刻 1 红；
4. **租户隔离 / RLS**（设计上）——15 条隔离用例含并发交替、fail-closed 全表、超管 DSN 下 `readyz` 必须 not_ready，且夹具在超管下 **fail 而非 skip**；
5. **仓储双实现分叉**——`validate_repository_parity.py`（20 个单元，12 类自检样本）；
6. **端点增删改**——`validate_openapi.py` G1 精确集合相等。

### 9.2 抓不住的（本轮实证的盲区）

1. **前端主链路**：浏览器级 e2e 只有匿名跳转，`登录→对话→工作台→插件安装` **0 条在跑**（R2-QA-02）；
2. **前端整站覆盖**：44% 的分母只有 12.4% 的源码（R2-QA-03）——页面级逻辑（25 个 page/layout）**完全未覆盖**；
3. **生产路径（PG 实现）的行为**：总覆盖 92.21% 里，`business/` 与 `api/` 多数 95–100%，而 PG 仓储实现只有 **66–88%**；两个实现只校验"形状一致"，不校验"行为一致"（R2-QA-14）；
4. **出站安全（SSRF / 插件网络沙箱）**：既无实现也无用例（R2-QA-06）；
5. **上传内容真实性**：改名伪装无对抗用例（R2-QA-07）；
6. **CI 本身能否跑**：整条适配层门禁因 PATH 未激活而必红（R2-QA-01），且预算冲突（R2-QA-05）——**即"门禁"与"测试"之间的连接线当前是断的**；
7. **文档与工件的一致性**：用例数归因（R2-QA-04）与覆盖率口径（R2-QA-13）都没有任何机械校验，全靠人写；
8. **资源收尾**：6 条 asyncpg `Connection._cancel` 未 await 的告警无人处理（R2-QA-15）。

### 9.3 一句话判断

> **测试本身是这套仓库最扎实的资产**：2366 条全绿、0 skip、断言 6241 条（3.0 条/用例）、单例复位彻底、**3/3 变异命中**、14 道门禁 13 道带自证、210 条 PG 红线用例本轮全部真跑。
> **但"验证体系"当前是断的**：CI 跑不起来（PATH 未激活 venv + 30min 预算已被 pytest 吃掉 79%），前端主线 e2e 不在任何自动化里，覆盖率三个口径六个数并存，PG 实现比内存实现低 15-30pt。
> 也就是说：**能力在，刹车没接上。** 第一轮 H-4 的"测试红线停摆"在**配置**上已修好（`ci-adapter.yml` 的 PG service + `--run-pg` + `skipped=0` 断言是正确修复），在**执行**上本轮已用本地实跑补上（2366/0/0/0，92.21%），但**CI 里那条线上至今没有一次绿色记录**。

1. **修 R2-QA-01（一行）+ R2-QA-05（拆 job / 抬超时）**，然后 `workflow_dispatch` 跑一次 —— 这一步把"门禁存在"变成"门禁在跑"，收益最大；
