# B5 气隙离线包试点方案（2026-11-07）

> **适用场景**：客户私有化 / 气隙（不可出网）环境的首次离线部署试点。
> **前置**：本方案不是通用上线方案，只覆盖「离线介质包加载/升级/回滚」这条链路；
> 其余安装、备份、安全基线仍按 `docs/deployment-guide.md` 执行。
> **验收依据**：`docs/delivery-2026-11-07-b5-offline-package.md`。
> **技术细节**：`docs/offline-package.md` §9–§11。

---

## 1. 试点目标与范围

### 1.1 目标

在客户真实目标机上，用**同一批次介质包**完成一次
「预检 → 校验 → 加载 → 冒烟 → 升级 → 回滚 → 回滚后再升级」，
并留下可复核证据。试点成功 = 验收文档第 4 节真机清单全部有证据。

### 1.2 范围

- 纳入：单机 lite compose 形态、离线介质加载、数据库迁移/回滚、插件导入、功能冒烟。
- 不纳入：`install.sh --offline` 一键安装（未接入）、K8s/HA、性能压测（B7）、
  客户定制模型效果、桌面/移动客户端。
- **前提事实**：3A/3B 的真实 skopeo/psql/cosign/插件导入尚未执行；
  首次真机生成也尚未执行。试点本身就是这些“未验证项”的第一次验证，
  在签字前**不得对外称“离线交付已验证”**。

| T0 | 试点日 | 加载 + 冒烟（S4–S5） | 实施工程师、客户业务验收人 |

**维护窗口**：执行 S6–S8 期间停止业务流量；窗口结束仍未完成 → 按 §5 中止并回滚。
建议窗口 ≥ 4 小时（含一次完整回滚）。

## 4. 回滚演练（试点前必须完成）

### 4.1 要求

- 必须在**演练环境**（非生产库）完成一次完整 `upgrade → rollback → 再次 upgrade`；
- 必须由实施工程师执行、DBA 核对数据库、见证人签字；
- 未完成演练 → 试点结论上限为「有条件通过」，且不得进入生产维护窗口。

### 4.2 演练步骤

1. 用与试点同批次的 `PKG_OLD` / `PKG_NEW`；
2. 在演练库执行 `load <PKG_OLD>` → 冒烟；
3. `upgrade <PKG_NEW>` → 冒烟 → 确认 `state.json` 有 `previous`；
4. `rollback` → 冒烟 → 确认版本回退、`previous=null`；
5. 再 `upgrade <PKG_NEW>` → 冒烟；
6. 额外做一次**回滚中途失败注入**（如临时改坏一个 down SQL 副本或用测试库权限拒绝），
   确认退出码 `3`、状态 `rollback_failed`、按人工介入可续跑；
7. 记录耗时、失败点与处置。

### 4.3 演练记录模板

| # | 步骤 | 计划耗时 | 实际耗时 | 退出码 | 关键输出/状态 | 是否通过 | 证据编号 | 异常与处置 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | load 旧版本 | 30 min | | | `status=loaded` | ☐ | EV-01 | |
| 2 | 冒烟 | 15 min | | | `ok`/`ready` | ☐ | EV-02 | |
| 3 | upgrade 新版本 | 30 min | | | `previous` 存在 | ☐ | EV-03 | |
| 4 | 升级后冒烟 | 15 min | | | 全过 | ☐ | EV-04 | |
| 5 | rollback | 30 min | | | `status=rolled_back` | ☐ | EV-05 | |
| 6 | 回滚后冒烟 | 15 min | | | 全过、数据完整 | ☐ | EV-06 | |
| 7 | 回滚后再升级 | 30 min | | | 版本回新 | ☐ | EV-07 | |
| 8 | 回滚中途失败注入 | 20 min | | | `exit 3` + pending | ☐ | EV-08 | |

**演练通过标准**：1–8 全部通过；rollback 总耗时 ≤ 维护窗口的 1/2；数据抽查无丢失；
失败注入场景未出现“报成功”。

## 5. 风险与中止条件

### 5.1 主要风险

| # | 风险 | 影响 | 预案 |
| --- | --- | --- | --- |
| R1 | 首次真机生成失败（镜像拉取/导出） | 无介质，试点延期 | T-7 完成；保留在线镜像来源备份 |
| R2 | 目标机磁盘不足 | 加载中断 | T-5 预检；预留 `totals.bytes + 20%/512 MiB` |
| R3 | 迁移权限/DSN 用错（应用角色做 DDL） | 迁移失败 | T-1 核对角色；DBA 现场待命 |
| R4 | 插件导入器不可用 | 插件步骤失败 | 提前提供包装脚本；失败则记录为条件项 |
| R5 | 回滚中途失败 | 混合状态 | 试点前演练；按人工介入指令，禁止起业务容器 |
| R6 | 维护窗口不足 | 未完成回滚 | 提前演练测时；窗口 ≥ 4h；超时即中止 |
| R7 | 介质批次混用 | 校验/指纹不符 | 只用同一批次；S2 双向校验 |

### 5.2 立即中止条件（硬停）

命中任一条，**当场停止上线并执行回滚**，不得“再试一次看看”：

1. `verify` 失败（哈希/签名/条目缺失/`MANIFEST` 不一致）；
2. `load` 连续失败 2 次且根因不明；
3. 迁移在数据库侧报错且 `rollback` 也不可用；
4. `rollback` 返回 `3`（中途失败）；
5. 回滚后冒烟失败或数据抽查发现丢失；
6. 介质指纹与已记录不一致、或现场使用了非交付批次；
7. 维护窗口剩余时间不足以完成一次完整回滚；
8. 客户方要求中止。

**中止后的动作顺序**：停止业务容器 → 保留现场（日志/`state.json`/`docker images`）→
按验收文档 §6 与 `docs/offline-package.md` §10.2 人工介入 → 通知双方签字人 → 另行排期。
