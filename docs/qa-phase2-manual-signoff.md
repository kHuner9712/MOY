## 一、填写规则（违反任一条，该行判「无效」）

1. **不得预填结论**：`实际` 与 `结论` 两列在真正执行前必须留空，禁止先写「通过」再补验证。
2. **`实际` 列写事实不写判断**：必须写"看到了什么"（例如「返回 `errcode=0`，`message_id` 非空，长度 32」「后台草稿箱出现 1 条草稿，状态 `draft`」），不得写「正常」「符合预期」「OK」。
3. **`凭证截图` 列必须是真实文件名**：截图存 `docs/qa-evidence-manual/`，命名 `ms-<序号>-<通道>-<操作>.png`，与该表格行一一对应。
4. **缺资质不得写「通过」**：未取得测试租户/证书/授权的行，`结论` 列只能填「**未验证**」，并在备注写明缺什么、由谁提供、预计时间。
5. **一条操作一行**：同一通道的多个操作分行记录，不允许合并成"整体联通正常"。
6. 执行人、日期必须手填真实信息；`结论` 只允许「通过」/「不通过」/「未验证」三种取值，不通过时须附缺陷编号。
