# Moy（麦子）V1.0 用户手册

> 适用版本：V1.0
> 适用读者：企业内的实际使用者（普通成员、部门负责人、企业管理员、行政/人事/运营/研发岗位）
> 编写口径：**按岗位场景组织**，不按菜单罗列。凡是你需要点的地方，都写清了"在哪、点什么、看到什么"。

---

## 1. 五分钟了解 Moy

Moy 是一个跨生态的办公助手：它把你的**企业资料**（文档、制度、方案）、**日常工具**（邮箱、代码仓库、企业微信、飞书、公众号）和**语言组织能力**放在同一个对话里，让你用一句话把一件事推进到"能直接用的产出"。

### 1.1 它擅长什么

| 场景 | 你能这样用 | 产出是什么 |
| --- | --- | --- |
| 查资料 | "按公司差旅制度，出差住宿标准是多少？" | 带出处的回答，可直接点开原文核对 |
| 写东西 | "把这份会议材料整理成纪要和待办" | 纪要与待办清单，可复制、可发出 |
| 走流程 | "帮我给候选人发面试邀约" | 邀约邮件正文 + 发送结果 |
| 干活 | 打开研发/内容/行政人事工作台，填几个输入 | 方案、代码、稿件、排期表、招聘说明等成稿 |

### 1.2 使用前的三个前提

1. 你已收到企业管理员发出的**邀请**，并完成账号激活；
2. 你所在的企业已开通功能（不同套餐可用的功能不同，见第 8 章）；
3. 需要用到工具（邮箱/代码仓库/企微/飞书/公众号）时，你要先在设置里**连接一次账号**。

### 1.3 界面地图

左侧导航从上到下：

| 导航 | 用来做什么 | 谁会常用 |
| --- | --- | --- |
| **对话** | 提问、写作、分析；上传文件直接问 | 所有人 |
| **知识库** | 建资料库、上传文档、看引用出处、设定可见范围 | 所有需要"让助手读过公司资料"的人 |
| **插件与工作台** | 添加工具与场景工作台；进入"已添加的插件" | 研发、内容运营、行政人事、管理者 |
| **工作流** | 查看已发起的任务进度与每一步产出 | 用过工作台的人 |
| **团队管理** | 邀请成员、设置角色与权限 | 企业所有者、组织管理员 |
| **组织架构** | 部门层级维护 | 企业所有者、组织管理员 |
| **套餐与账单** | 看套餐、用量、额度、账单 | 企业所有者、组织管理员 |
| **个人中心** | 个人资料、账号设置 | 所有人 |
| **我的记忆** | 看/删助手记住的关于你的信息，开关记忆 | 所有人 |

> 页面上看不到"团队管理/组织架构/套餐与账单"，通常是因为你的角色是普通成员——这不是故障，是权限设计（见第 6 章）。

## 2. 快速上手（15 分钟走完三步）

### 2.1 第一步：登录

1. 打开管理员给你的地址（形如 `http://<企业服务器地址>`）；
2. 用企业统一账号登录（若企业已接入统一身份，会跳到企业登录页）；
3. 首次登录后到「个人中心」确认姓名与邮箱正确——**助手会用你的身份署名对外发出内容**。

遇到"登录状态已失效，请重新登录"：直接重新登录即可，这是令牌到期后的正常提示。

### 2.2 第二步：发起第一次对话

1. 点左侧「对话」；
2. 在底部输入框输入问题（例：`帮我写一份给新同事的入职第一周安排`）；
3. 回车发送，等待回复。

对话页能做的三件事：

| 动作 | 怎么做 | 说明 |
| --- | --- | --- |
| 切换助手能力 | 输入框旁的能力选择 | 通用助手/编程助手/长文档助手/深度推理助手，见 2.4 |
| 上传文件问 | 输入框的附件按钮 | 支持 PDF、Word、Excel、PowerPoint、纯文本、Markdown 等常见格式；单文件上限 50 MB |
| 找回历史 | 左侧会话列表 | 刷新页面、换浏览器都能看到；漏掉的对话不会丢 |

### 2.3 第三步：上传一份文档并提问

1. 点输入框附件按钮，选一份 PDF 或 Word；
2. 等文件状态从"处理中"变成"可用"（大文件需要等一会）；
3. 提问，例如"这份合同的付款节点是哪几个？违约责任怎么写的？"；
4. 回答里出现小角标（引用标记），点开能看到**第几页、第几段**的原文。

> 若提示"文档还在处理中，请稍候查看"，等 1–2 分钟再提问即可。文档没处理完就提问，助手读不到它。

### 2.4 四种助手能力怎么选

| 能力 | 适合 | 不适合 |
| --- | --- | --- |
| 通用助手 | 日常问答、写文档、整理信息 | 超长文档通读 |
| 编程助手 | 写代码、解释代码、排查报错 | 长篇报告 |
| 长文档助手 | 上百页报告、合同、手册的通读与摘要 | 短问答（浪费额度） |
| 深度推理助手 | 复杂问题拆解、多步推理、方案权衡 | 简单事务 |

> 能力档位决定"读多长的上下文"。选错档位最典型的后果是"它没看完我的文档就回答了"——长文档请用长文档助手。

## 3. 对话与历史会话

### 3.1 会话列表

- 每个会话自动命名；可在会话上改标题或归档，让列表干净。
- 会话**保存在服务器**：换电脑、换浏览器登录，历史都在。
- 删除会话是**软删除**：30 天内可由管理员协助恢复（恢复窗口见企业配置），到期后彻底清除。

### 3.2 一次对话里它怎么用你的资料

1. 先看你这轮说的话；
2. 再看相关企业资料（如果你把资料放进了知识库并选中）；
3. 需要工具时调用工具（例如发邮件、查仓库）；
4. 生成回答，并标注它引用了哪些资料。

**它不会凭空编造引用**：没有可靠出处时，会明确说明"没有找到相关资料"，而不是给你一个看起来很像的答案。看到这种说明，请补资料或换一种问法。

### 3.3 中断与失败

| 你看到的 | 含义 | 怎么办 |
| --- | --- | --- |
| 回答只出了一半就停 | 网络断开或页面被关掉 | 保留的内容已存下，重新提问即可 |
| "AI 暂时没有给出回答，请重试" | 上游服务瞬时失败 | 直接重试（通常一次就好） |
| "当前对话内容过长，请新建会话或精简内容" | 这一轮上下文超出上限 | 新建会话，或把关键信息精简后再问 |
| "当前使用人数较多，请稍后再试" | 触发了频率保护 | 等 1 分钟 |

## 4. 知识库（让助手真正"读过公司资料"）

### 4.1 建立知识库

「知识库」→ 新建，填写：

| 字段 | 怎么填 | 影响 |
| --- | --- | --- |
| 名称 | 让人一眼看懂（例：`2026 差旅与报销制度`） | 找库时靠它 |
| 描述 | 一句话说明这个库收什么、谁用 | 便于同事判断要不要引用 |
| 可见范围 | 全企业 / 仅自己 / 指定成员 | **决定谁能看到里面的资料，见 4.4** |
| 切分精细度 | 默认即可 | 影响检索颗粒度；制度类文档建议按段落（默认） |

### 4.2 上传与管理文档

- 支持 PDF、Word、Excel、PowerPoint、纯文本、Markdown 等常见格式（**具体格式清单由部署的内容处理组件版本决定**；上传不支持的格式会提示"暂不支持该格式的文档"）。
- 单文件上限 **50 MB**；单个知识库的文档条数上限与套餐有关（免费版 50 条 / 专业版 2000 条 / 企业版 10000 条）。
- 上传后有三个状态：**处理中 → 可用 → 失败**。
- 失败常见原因：扫描件没有文字层（需要先做文字识别）、文件加密、格式不支持。提示语会直接告诉你原因。
- 重新处理：文档更新后，请**重新上传新版本**而不是手工改旧文件——引用的页码与段落依赖原始版本。

### 4.3 引用溯源怎么看

回答里带角标的句子，点开角标会展开引用抽屉：

| 抽屉里显示 | 含义 |
| --- | --- |
| 文档名称 | 这句话来自哪份文件 |
| `第 3 页 · 第 2 段` | 精确位置（无页码的格式只显示段落） |
| 原文片段 | 被引用的原始文字 |
| "该引用来自旧版本内容，原文已更新" | 你看的是当时回答所用的版本，文件之后被更新过 |

这条提示很关键：**它说明回答没错，只是文件变了**。涉及制度、合同的结论，请以最新版本为准重新提问一次。

### 4.4 可见范围与授权（企业资料最容易出事的地方）

| 范围 | 谁能看 | 适用 |
| --- | --- | --- |
| 全企业 | 企业内所有成员 | 制度、公共手册 |
| 仅自己 | 只有你 | 个人草稿、个人整理的资料 |
| 指定成员 | 你授权的人（可含部门） | 项目资料、部门内部资料 |

规则：

1. **只有被授权的人能检索到库里的内容**，没被授权的人连库名都看不到；
2. 授权由库的创建者/管理者维护，在知识库详情的"授权"面板里加人；
3. 权限只在**知识库层**判定；同一个人能看到库，就能看到库内全部文档（V1.0 不支持"同一库里的单篇文档单独授权"）；
4. 员工离职或转岗后，请及时回收授权——系统不会自动回收。

### 4.5 知识库能用多少（按套餐）

| 套餐 | 知识库数量 | 单库文档数 |
| --- | --- | --- |
| 免费版 | 3 个 | 50 条 |
| 专业版 | 不限 | 2000 条 |
| 企业版 | 不限 | 10000 条 |

## 5. 工作台（按岗位的场景化入口）

工作台不是"另一个聊天框"，而是**把一个岗位的常规活儿拆成固定步骤**：你填几个输入，它一步步产出，每一步的成果你都能看、能改、能拿走，中途离开也不会丢。

进入方式：左侧「插件与工作台」→ 添加工作台 → 在"已添加的插件"下点进去（或直接在左侧分组里点）。

### 5.1 研发岗位：前端研发工作台

> **解决什么问题**：从"一句话需求"到"仓库里的一次提交"，中间那些写方案、生成文件、提交、核查的动作，一个人要来回切工具、反复对齐。

**输入**：需求标题、需求描述、目标仓库、分支策略、技术栈偏好、参考文档。

**过程与产出**（每一步都有独立产出，可单独查看/复制）：

| 步骤 | 产出 | 你需要做什么 |
| --- | --- | --- |
| 1 | **需求要点**（把模糊需求拆成可执行点） | 核对有没有理解偏 |
| 2 | **技术方案** | **必须确认**后才继续 |
| 3 | **代码文件** + **用例文件** | 下载或直接取用 |
| 4 | **提交记录** + **合并请求** | 提交前**必须再确认一次** |

**适合谁**：前端/全栈工程师、技术负责人。
**不适合**：需要人工评审架构决策的核心模块（用它写初稿，决策仍归人）。

### 5.2 内容运营岗位：内容运营工作台

> **解决什么问题**：一个主题要出多平台稿件 + 排期表，检索素材、想选题、按平台改写、排期、发布，一人一天做不完。

**输入**：运营主题、目标平台、目标受众、时间窗、素材来源。

**过程与产出**：

| 步骤 | 产出 | 说明 |
| --- | --- | --- |
| 1 | **素材要点** | 从企业资料里检索；**没有可靠素材会如实标注，不编造** |
| 2 | **选题与标题候选** | 多个角度，供你挑 |
| 3 | **平台稿件** + **配图建议** | 按各平台风格分别成稿 |
| 4 | **发布排期表** | 四列（内容/平台/时间/负责人），可导出 |
| 5 | **发布回执** | 已接入的平台直接发布；**未接入的平台显示"待人工发布"，并给你可下载的稿件与发布指引** |

**一个必须知道的诚实设定**：它**不会伪造发布成功的回执**。没接入的平台就显示"待人工发布"——这比给你一个假回执有用。

**适合谁**：内容运营、市场、品牌。
**默认平台**：微信公众号、邮件。

### 5.3 行政人事岗位：行政人事工作台

> **解决什么问题**：招聘说明、简历初评、面试提纲、邀约、录用通知、各类公文——事情碎、格式多、每件都要对外发。

**输入**：岗位名称、所属部门、职责要点、硬性要求、简历文件、公文类型、公文要素。

**过程与产出**：

| 步骤 | 产出 | 说明 |
| --- | --- | --- |
| 1 | **招聘说明**（JD） | 按岗位与部门生成 |
| 2 | **筛选评分表** | 按简历逐项评分，**结论可辩驳**（能看到为什么给这个分） |
| 3 | **面试提纲** | 针对候选人背景的追问点 |
| 4 | **邀约回执** | 经你确认后发出（邮件/飞书/企微） |
| 5 | **录用通知草稿** | **所有涉及金额的位置一律留空由你填写** |
| 6 | **公文文件** | 按公文类型与要素生成 |

**两条硬规矩**：

1. **金额字段永远留空**——薪资、补贴、赔偿等必须由你填，系统不猜；
2. **对外发送前一定会先请你确认**。

简历无法读取时会如实标注（例如扫描件没有文字层），**不会猜测内容**。

**适合谁**：HR、行政、部门负责人。

### 5.4 三个轻量工具（无需进入工作台）

| 工具 | 输入 | 产出 |
| --- | --- | --- |
| 邮件起草 | 收件人、邮件目的、要说清的要点、语气 | 邮件正文 + 发送结果 |
| 周报生成 | 汇报周期、本周重点、收件人 | 本周记录要点 + 周报正文 + 发送状态 |
| 会议纪要 | 会议名称、会议材料 | 议题与结论 + 会议纪要 + 归档链接 |

### 5.5 任务进度在哪看

- 左侧「工作流」→ 任务列表 → 点进某个任务看每一步。
- 每一步会显示：产出内容、状态（成功/失败/待确认）、失败原因与"该怎么补"。
- **离开页面任务会继续推进**，回来能看到中间每一步留下了什么。

## 6. 团队协作

### 6.1 邀请成员

「团队管理」→ 邀请成员：

1. 填邮箱（可批量）；
2. 选角色（决定他能看到哪些菜单、能做哪些操作，见 6.3）；
3. 关联部门（决定他默认能看到哪些部门资料的口径）；
4. 发出邀请。对方在有效期内完成激活即可登录。

**席位限制**：可邀请人数受套餐席位约束。提示"成员席位已用满，请先增加席位"时，到「套餐与账单」增加席位或移除不再使用的成员。

### 6.2 组织架构

「组织架构」维护部门层级：

- 部门可多层嵌套；成员可归属一个主部门；
- 删除部门前必须先迁走成员与子部门（否则提示"该部门下仍有成员或子部门，请先迁移后再删除"）；
- 部门用途：作为知识库授权的对象、作为管理视图的统计维度。

### 6.3 四个角色能做什么

| 能力 | 企业所有者 | 组织管理员 | 普通成员 | 访客 |
| --- | --- | --- | --- | --- |
| 日常对话、用工作台 | ✅ | ✅ | ✅ | ✅ |
| 建/改/删自己的知识库 | ✅ | ✅ | ✅ | ❌ |
| 上传/删除自己库里的文档 | ✅ | ✅ | ✅ | ❌ |
| 查看被授权的知识库 | ✅ | ✅ | ✅ | ✅（只读） |
| 连接工具账号（邮箱/仓库/企微/飞书/公众号） | ✅ | ✅ | ✅ | ✅ |
| 管理知识库授权 | ✅ | ✅ | ❌ | ❌ |
| 邀请/修改成员 | ✅ | ✅ | ❌ | ❌ |
| 维护部门结构 | ✅ | ✅ | ❌ | ❌ |
| 维护角色与权限 | ✅ | ✅ | ❌ | ❌ |
| 查看操作记录 | ✅ | ✅ | ❌ | ❌ |
| 查看套餐与用量 | ✅ | ✅ | ✅（只看） | ✅（只看） |
| 变更套餐 / 调整席位 | ✅ | ✅ | ❌ | ❌ |
| 导出/删除企业数据 | ✅（仅所有者） | ❌ | ❌ | ❌ |

补充规则：

1. **企业所有者不能被直接移除**，必须先把所有权转给别人（提示"不能移除企业所有者，请先转移所有权"）；
2. **不能修改与自己同级或更高级的成员**；
3. 角色是"能力的上限"，**具体某份资料能不能看，还要看知识库授权**——两层都过才行。

### 6.4 连接工具账号（一次性动作）

「插件与工作台」→ 添加工具 → 按提示完成授权。

| 工具 | 用途 | 授权方式 |
| --- | --- | --- |
| 邮箱 | 发邮件、看邮件 | 邮箱账号授权 |
| 代码仓库（GitHub） | 读写仓库、提合并请求 | 账号授权 |
| 企业微信 | 发消息、建群 | 企业应用授权 |
| 飞书 | 发消息、建文档 | 账号授权 |
| 微信公众号 | 上传素材、发布文章 | 公众号授权 |

- 授权凭证**加密保存在服务器**，页面与日志里都不显示明文。
- 提示"工具授权已过期，请重新连接"时，重新点一次授权即可。
- 提示"该工具尚未连接，请先在设置中完成授权"时，说明还没连过或连接被移除。

## 7. 记忆（你的偏好会被记住，也要能被删掉）

这是最需要讲清楚的一块：**它记住什么、记在哪、怎么删**。

### 7.1 它会记住哪些信息

只记**六类**与你工作相关的信息：

| 类别 | 例子 |
| --- | --- |
| 身份与称呼 | "大家都叫我小林""我是华东区销售" |
| 组织信息 | "我在产品部，向张总汇报" |
| 偏好 | "回复尽量简短，先给结论" |
| 口径与常用说法 | "我们把客户叫'甲方'""金额统一用万元" |
| 约束与注意事项 | "对外文件不要出现内部项目代号" |
| 项目背景 | "Q4 重点是华东区续约" |

### 7.2 它**永远不会**记住的内容

命中以下任一情况，信息会被**直接丢弃，不落库、不出现在任何地方**：

- 身份证号、银行卡号、手机号；
- 任何"密码/口令/密钥/私钥/凭据/令牌"类字样；
- 健康与宗教类信息（病史、疾病、用药、手术、信仰、宗教活动等）。

> 这不是"事后删除"，而是**入口就丢**。所以你不用担心"说漏了一句就被永久记住"。

### 7.3 在哪看、怎么删

「我的记忆」页面（左侧导航最下方）：

| 操作 | 效果 |
| --- | --- |
| 列表 / 按类别筛选 | 看到它记住的每一条，含类别与记录时间 |
| 删单条 | 立即失效，从此回答里不再使用 |
| 按类别清空 | 该类别全部清除 |
| 全部清空 | 一次清干净 |
| 记忆开关 | 关掉后：不再从新对话里记东西；**已记住的仍保留，需要你自己删** |
| 分类开关 | 只影响该类别（关掉后该类不再记录、也不再使用，已有条目保留） |

**删除的实际效果**：删掉后，**新对话不会再出现这条信息**；历史对话里已经生成的回答不会被改写（那是当时的记录）。

### 7.4 记忆的边界

- 记忆是**按人**的，不跨人共享：你的偏好不会影响同事的对话。
- 记忆有总量上限（默认每人 200 条），超出后自动淘汰最久未使用的条目。
- 涉密项目建议直接**关闭记忆**：记忆能提升顺手程度，但也会把项目信息留在你的个人记忆里。

## 8. 计费与额度

### 8.1 三个档位的差别

| 项 | 免费版 | 专业版 | 企业版 |
| --- | --- | --- | --- |
| 价格 | 0 | 39 元/席位/月 | 99 元/席位/月 |
| 起购席位 | 3 | 5 | 20 |
| 每席位每月可用量 | 20 万单位 | 300 万单位 | 800 万单位 |
| 知识库数量 | 3 个 | 不限 | 不限 |
| 单库文档数 | 50 | 2000 | 10000 |
| 可连接工具数 | 1 | 5 | 5 |
| 插件与工作台市场 | ❌ | ✅ | ✅ |
| 组织架构 / 角色权限 | ❌ | ✅ | ✅ |
| 操作记录（审计） | ❌ | ✅ | ✅ |
| 私有化部署 | ❌ | ❌ | ✅ |
| 试用期 | 无 | 14 天 | 30 天 |

### 8.2 额度是怎么算的

- 额度按"用量单位"计，四种能力分别计量：**智能对话、文档问答、文档处理、自动化任务**。
- 单位数取决于内容长度；**文档处理按文件大小折算**（文件越大，消耗越多）。
- 用量在「套餐与账单」→ 用量明细里按能力、按成员、按时间查看。

### 8.3 额度用到 80% 与 100% 分别会怎样

| 水位 | 平台行为 | 你要做什么 |
| --- | --- | --- |
| **80%** | 提示"本月可用量已用到八成，建议联系管理员提前调整"——**只是提示，不拦任何操作** | 管理员评估是否加席位或升档 |
| **100%** | 对话类请求被拦下，提示"本月可用量已用完，请联系管理员调整" | 管理员加席位/升档，或等下月重置 |

**文档处理在额度用尽时的特别行为**（重要）：

- 你上传的文档**会被保存**，但不会被处理。界面提示：**"额度已用尽，文档已保存但未处理；额度恢复后请重新上传"**。
- 为什么必须重新上传：平台不保存上传文件的原始字节（出于数据最小化），额度恢复后无法自动重跑。
- 所以：额度接近上限时，**先处理重要文档**，不要批量堆积。

### 8.4 升级/降级/加席位

「套餐与账单」：

| 操作 | 生效时点 | 注意 |
| --- | --- | --- |
| 升档 | 支付后立即生效 | 已有数据不受影响 |
| 加席位 | 支付后立即生效 | 可立即邀请更多成员 |
| 降档 | **当前计费周期结束后生效** | 提示"降级将在当前周期结束后生效"；降档后超出上限的知识库/文档会变为只读，需先精简 |
| 有未支付订单时再下单 | 不允许 | 提示"当前账户有未完成订单，请先完成支付" |

支付完成后页面会自动刷新订阅状态；若长时间未变，点「套餐与账单」页的刷新，或联系管理员确认支付结果。

## 9. 常见问题（15 条）

**Q1：登录后什么菜单都看不到，只有一个对话？**
你的角色是普通成员/访客，管理类菜单按设计不可见（见 6.3）。需要更多权限请找企业管理员调整角色。

**Q2：为什么它说"没有找到相关资料"，但我明明上传了文档？**
三种常见原因：① 文档还在"处理中"；② 文档不在你当前选中/有权限的知识库里；③ 问题是"全年数据汇总"这类需要跨多份文档统计的问题——它只会如实引用找到的片段，不会替你算跨文件汇总。处理办法见 4.2、4.4。

**Q3：引用里的页码对不上我打开的 PDF。**
引用记录的是**当时那一版**的页码。如果文件之后被替换过，会显示"该引用来自旧版本内容，原文已更新"。请以最新版本重新提问。

**Q4：能不能让某个同事只看到一份文档，看不到同库其它文档？**
V1.0 不支持单篇文档授权。请把这份文档**单独建成一个知识库**，只授权给该同事。

**Q5：任务跑到一半我关了页面，会白做吗？**
不会。任务在服务器继续推进，回到「工作流」能看到每一步产出与状态。

**Q6：工作台提示"未接入的平台"，是不是出错了？**
不是。未接入的平台会显示"待人工发布"，并给你可下载的稿件与发布指引。**平台不会伪造发布成功回执**。

**Q7：为什么录用通知里的薪资是空的？**
这是刻意的安全设计：所有涉及金额的字段一律留空由人填写，系统不猜金额。

**Q8：它记住了我上次说的偏好，我不想让它记，怎么办？**
到「我的记忆」删掉那一条，或在页面顶部关掉记忆开关（关掉后不再记新的，但已有的要自己删）。

**Q9：我在对话里说了身份证号，会不会被存下来？**
不会。身份证号、银行卡号、手机号、密码类、健康与宗教类信息在**进入记忆之前就被丢弃**，不落库。

**Q10：上传文件提示"文件超出大小限制（上限 50MB）"。**
单文件上限 50 MB。请压缩、拆分或改成正文粘贴。扫描版 PDF 建议先做文字识别再上传。

**Q11：提示"成员席位已用满，请先增加席位"。**
套餐席位用完了。到「套餐与账单」加席位，或移除不再使用的成员后再邀请。

**Q12：提示"当前账号没有该操作的权限"。**
两层原因：① 你的角色没有这个权限点；② 你有权限点，但这份资料没授权给你。前者找管理员调角色，后者找知识库的创建者要授权。

**Q13：企业数据怎么导出？离职/合同到期要清空数据怎么办？**
这是**企业所有者**才能做的操作（私有化部署由运维执行全库脚本，见部署手册"DBA 脚本"章）：
- **导出**：一次生成导出包（操作记录/用量/会话与消息/记忆/产物清单），生成完直接给短期下载地址；数据量特别大时会提示"数据量较大，请联系管理员分批导出"，**不会静默截断**。
- **删除**：需要二次确认（逐字输入企业名称）。删除会先停用企业以阻断后续写入，再逐表清除，并生成**删除证明**。操作记录受"只增不改"保护，需由运维按证明里的说明单独清理。

**Q14：删掉的会话还能找回吗？**
删除是软删除，**30 天内**（以企业配置为准）可由管理员协助恢复；到期后彻底清除。

**Q15：页面提示"当前使用人数较多，请稍后再试"。**
触发了频率保护（默认每人每分钟 120 次请求）。等一分钟即可；如果是团队集中使用，请联系管理员评估扩容。

## 11. 遇到问题怎么反馈

一次性备齐这四项，能省一半往返：

1. 你当时在哪个页面、点了什么、期望看到什么；
2. 页面提示的**完整原文**（截图，不要只描述）；
3. 发生时间（含时区）；
4. 是否能稳定复现（换个会话/换个文件再试一次的结果）。

**不要**在反馈里粘贴密码、授权凭证、客户身份证等敏感信息。
