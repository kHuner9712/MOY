## 七、流程教训（写进团队 SOP）

1. **共享分支禁止 `git rebase` / `git reset`**：B13 首个提交 `29032cb` 曾被 `reset --soft` 从历史里抹掉（内容未丢，但提交丢失），只允许追加提交或 `git revert`。
2. **禁止双人同改同一棵树**：B05/B07 两轮出现「QA 正在测的树 ≠ 工程师正在改的树」，最终靠「QA 用 `git archive <sha>` 导出隔离复核」解决，此后成为标准做法。
3. **自称缺陷必须给最小复现**：`P1-03`（缺唯一索引）是工程师查错表名的误报，浪费一轮沟通；反例是 QA 的 `W3-05`，用「先跑失败通知再跑成功通知」钉死了 P0，无可辩驳。
4. **门禁必须能红**：G-24 曾因 0 条 `p0` 标记而「永远绿」，G-17 扫描器曾因词表漂移失效；现所有扫描器都要求 `--self-test` 且**自检通过返回 1**。
5. **覆盖率要固定测量位置**：`--cov` 会扫 `.next` 下的 `.mjs`，导致数字随构建产物漂移；测量前必须清缓存，或固定 `COVERAGE_FILE`。
