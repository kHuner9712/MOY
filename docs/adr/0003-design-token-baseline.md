## 一、背景

总方案 1.2 核心设计原则第 5 条：「**体验一致性**——全产品 UI、交互逻辑、文案风格 100% 统一，
插件不得使用独立设计规范」。

总方案 3.5 前端交互层核心改造任务第 1 条：「重新设计整体视觉风格，去掉 Open WebUI 原生样式，
打造独立产品品牌视觉；统一所有组件、按钮、弹窗、表单的交互规范」。

第 6.2 节 AC-04 验收标准：「全产品 UI 走查无设计走样；插件前端组件 100% 使用平台统一组件库，
无自定义 UI」。

**问题**：设计令牌（Design Token）是「统一组件库」与「独立品牌视觉」的技术底座——所有按钮、弹窗、
表单、间距、字号、圆角、色彩语义都从令牌派生。Sprint 0 已完成组件库骨架（`apps/web/src/components/ui/`
下 badge/button/card/dialog/feedback/input/toast 共 7 类组件），但**当前令牌取值尚未确定**。

**风险（若不决策）**：
1. 第 3 周 T03 组件库开工后，令牌一旦写死再调整，将触发全组件返工，返工量随页面数线性增长；
2. 各页面由不同人并行开发时，无令牌基线必然产生「同色不同值」，直接违反 AC-04；
3. 插件层（S3）的 UI 扩展点以「平台统一组件库」为唯一渲染来源，令牌不定则插件规范无法冻结。

**决策时限**：必须在**第 3 周 T03 开工前**确定，否则组件库返工风险不可接受。

## 二、待决内容（决策项清单）

> 本 ADR 为占位，以下为需拍板的具体决策项。每一项均给出架构师的**建议默认值**，
> 以便产品经理在此基础上「确认或修改」而非从零设计。

### 2.1 色彩令牌（建议默认值）

| 语义令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--color-primary` | 待定（建议：主色 1 套 + 悬停/按下 2 档派生） | 主按钮、选中态、链接、焦点环 |
| `--color-primary-hover` / `--color-primary-active` | 由主色派生 | 交互态 |
| `--color-surface` / `--color-surface-muted` | 待定（建议：白 / 浅灰） | 卡片、面板、次级区域 |
| `--color-background` | 待定（建议：近白或极浅冷灰） | 页面底色 |
| `--color-text-primary` / `--color-text-secondary` / `--color-text-muted` | 待定 | 文本三级层次 |
| `--color-border` | 待定 | 分隔线、输入框描边 |
| `--color-success` / `--color-warning` / `--color-danger` / `--color-info` | 待定 | 状态语义色 |
| `--color-focus-ring` | 待定（建议：主色 30% 透明） | 无障碍焦点环 |

**约束（AC-06 关联）**：语义令牌命名不得出现任何技术术语；`--color-primary` 的
**对外文案标签**为「主要操作」，禁止使用「模型」「向量」「Agent」等词。

**无障碍底线**：正文与背景对比度 ≥ 4.5:1，大字号 ≥ 3:1；状态色不得作为唯一信息载体
（须配图标或文字），满足总方案 5.4「敏感数据脱敏」与可访问性基本要求。

### 2.2 字体与排版

| 项 | 建议默认值 |
| --- | --- |
| 中文字体栈 | 系统中文字体优先（PingFang SC / Microsoft YaHei / Source Han Sans） |
| 西文字体栈 | 系统 UI 字体优先（system-ui） |
| 等宽字体栈 | 用于代码辅助场景（P0-05），系统等宽优先（ui-monospace） |
| 基础字号 / 行高 | 14px / 1.6（正文），12px（辅助），16px / 1.5（正文强调） |
| 字重档位 | 400（正文）/ 500（强调）/ 600（标题），不超过 3 档 |
| 标题层级 | H1~H4 四级，层级间距统一由令牌控制 |

**约束**：不得引入需在线加载的第三方字体（影响首屏 ≤ 2s 与私有化离线环境）。

### 2.3 间距 / 圆角 / 阴影 / 动效

| 令牌组 | 建议默认值 |
| --- | --- |
| 间距刻度 | 4px 基准：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64` |
| 圆角 | `sm=4px / md=8px / lg=12px / full=9999px`（胶囊/头像） |
| 阴影 | 2 级（卡片、浮层），弱阴影优先，暗色模式不做纯黑 |
| 动效时长 | 快速 120ms / 标准 200ms / 慢速 320ms；缓动统一 |
| 动效原则 | 遵循 `prefers-reduced-motion`；加载态必须有明确动画（总方案 3.5-3） |

### 2.4 组件状态矩阵

每个组件必须齐备的状态集（缺一即为组件不完整，AC-04 走查不通过）：

| 状态 | 要求 |
| --- | --- |
| 默认 / 悬停 / 焦点 / 激活 / 禁用 | 五态齐备 |
| 加载中 | 明确的加载动画（禁用态 + 动画），禁止「点了没反应」 |
| 错误 | 就地错误提示 + 解决建议文案（总方案 5.5） |
| 空状态 | 每个数据容器组件需有空态设计与引导文案 |
| 骨架屏 | 首屏与列表加载优先使用骨架屏，避免布局跳动 |

### 2.5 落地形式

| 项 | 决策点 |
| --- | --- |
| 令牌载体 | 建议：CSS 变量 + Tailwind `theme.extend` 映射（`apps/web/src/styles/globals.css` + `tailwind.config.ts`） |
| 深色模式 | **V1.0 是否需要**？建议：**不做**（PRD 6 大页面范围已满，深色模式非 AC 要求，避免返工） |
| 令牌文件位置 | 建议：`apps/web/src/styles/tokens.css`（单一事实来源，组件与插件均从此引用） |

## 三、备选方案（针对「深色模式是否纳入 V1.0」）

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. V1.0 含深色模式 | 令牌需定义双值（light/dark），组件需全量适配 | ❌ 建议否决：非 AC-04/AC-06 验收项，S1/S2 资源应投入对话与知识库主链路 |
| B. V1.0 不含深色模式，令牌预留 dark 命名空间 | 令牌结构预留 `light` 命名空间，后续可扩展 | ✅ **建议采纳** |

## 四、影响与收益

| 维度 | 影响 |
| --- | --- |
| AC-04（交互一致性） | 令牌是「100% 统一」可验证的技术前提 |
| AC-06（无技术暴露） | 令牌命名与对外文案标签的约束在此处落实 |
| AC-07（首屏 ≤ 2s） | 禁止在线字体、限制阴影/滤镜层数 |
| T03 排期 | 决策必须在第 3 周前完成，否则组件库返工 |
| S3 插件规范 | 统一组件库是插件 UI 唯一来源，令牌冻结后插件规范方可冻结 |
| 前端代码 | 组件中禁止出现硬编码色值/字号/间距，一律引用令牌（可加 CI 扫描） |
