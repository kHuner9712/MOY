## 1. 背景

2026-11-04 产出三份文件（设计、规格、计划）。规格 §0 挂了四条冻结条件，其中 ②③ 由工程可满足，①（创始人签署）与 ④（战略复审）必须由创始人裁定；计划 §4 的五个拍板项里，D3 是唯一「无默认值即停工」的一条。

创始人当日指示「你帮我做决策即可」。本 ADR 即为该授权的行使记录：**决策由主理人代拟，后果由创始人承担**，与 ADR-0004（2026-10-21 授权代决）同一体例。

## 3. D-53 详解：为什么反过来保总纲、废战略

这是本次唯一一处**推翻既有结论**的裁定，必须写清逻辑，否则半年后会有人拿战略文档来反驳。

**两份文件的原始主张**

- 总纲 §6 / §6.1 / §13 原则二：保持广泛的市场入口，不预先锁定单一垂直。
- 战略文档 §1 / §4.1：不做通用工作台，只做一个垂直（W1 行政人事/公文），先做 10 个客户再谈平台。

**裁定**

| 条款 | 裁定 | 理由 |
| --- | --- | --- |
| 总纲 §6 / §6.1 / §13 原则二 / §12.5 | **保留** | 「底座 + 相」的结构本身就是广泛入口——只是入口不再由产品形态提供，而由**相**提供。总纲这句话在 10 月是对的，在 11 月的结构下依然是对的 |
| 战略 §1「不做通用 AI 工作台」 | **作废** | 它把「做不到」当成了「不该做」。真正的约束不是形态，而是**先付 141 人日**；形态可以是横向的，节奏必须是窄的 |
| 战略 §4.1「只做一个垂直」 | **作废** | 垂直假设成立的前提是「没有分发能力，只能靠窄口换可交付」。底座路线把这个「窄」从**产品层下移到相层**：产品横向，销售仍窄 |
| 战略 §3.1 / §5 / §6 / §7 / §8.4 | **保留** | 营收量级、单位经济红线、获客动作、组织切分、不拿 10x VC 的钱——这些与产品形态无关，继续有效 |

**新口径（替代原 §4.1）**

> 底座按横向建（P1–P4，141 人日）；销售按窄口打，首批三个相：**行政/公文、销售、财务**。相的自研顺序不按市场规模排，按「现有代码复用度 × 交付成本」排。

**代价（必须写进来，不能只写好处）**

1. **141 人日必须先付**，且前 4 周（P1）交付的是「装相/回放/审计」这类客户看不见的地基，销售现场没有新东西可讲。
2. **相的自研压力前 6 个月最大**：三个相都只能自研（D-48 限定 `first_party`），社区供给要等 V1.1。
3. **单位经济红线不变**：席位年费 ≥2400 元、首年合同 ≥18 万、实施 ≤25 人日。底座再完整，也不能接低于这条线的单。

## 4. D-50 详解：为什么是 PG 而不是对象存储

| 方案 | 优点 | 否决/采纳理由 |
| --- | --- | --- |
| **A：PG 分区表 + 归档（采纳）** | 与现有 `tenant_scope` + RLS 同一套；事务性保证 `seq` 连续无空洞；fork / 回放是范围查询；气隙环境只需一个 PG | 写入放大是主要风险，用 delta 采样 + 90 天归档对冲 |
| B：对象存储 JSONL 直写 | 写入吞吐高，天然 append-only | 无事务、无 RLS、范围查询要靠索引文件；fork 与断线续传要自己造一套偏移管理；改回 A 的返工约 18 人日 |
| C：PG + 对象存储双写 | 兼顾热冷 | V1.0 多一套一致性负担，收益在 90 天归档后才出现 |

**落地约束**

1. 主键 `(session_id, seq)`，`prev_hash` 逐条链式；`tenant_id` 必填并进 RLS 策略。
2. 分区键 `HASH(session_id)` 16 片；分区数写入迁移脚本常量，不运行时改。
3. 90 天归档为 JSONL + 链头，归档后原分区可 detach；归档文件必须能被 `moy-xiang-verify` 同款脚本复算。
4. `model.delta` 类高频事件采样落库（只存首尾 + 摘要），否则行数会到 turn 数的 20 倍。

## 5. D-48 详解：允许脚本的边界

- 允许：`skills[].kind = script`，必须同时声明 `requires_sandbox = true` 与 `permissions.sandbox_mode`。
- 不允许：脚本以宿主权限执行（这是 dsh 的已知问题，原文「插件继承宿主权限」）。
- 不允许：V1.0 装载 `provenance.source ≠ first_party` 的相——签名信任链尚未具备撤销能力。
- 因此：**T06（权限与沙箱，18 人日）不可砍**。砍它，「美工相」在技术上不成立，「最小权限」在实现上是假的。
