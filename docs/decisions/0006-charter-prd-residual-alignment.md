## 四、逐项两方案利弊与裁决

### 4.1 AL-26 成熟度列（高）

- **方案 A（总纲优先）**：按审计事实重标 P0-06/11/12/13/20，成熟度列加「复核日期 + 责任人」，后续由证据脚本生成、禁手填。
  - 利：一次消除高报与低报，尽调可自证；符合总纲 §11「五级状态不等价」。
  - 弊：重标后 G1 指标更难看；需工程出证据（S-M）。
- **方案 B（现状优先）**：只改单点数字，机制不动。
  - 利：S 级，改动最小。
  - 弊：下批交付后必然再次失真，每轮审计复发。
- **裁决：A**。依据：charter:415（不得把设想写成事实）+ ADR-0005 §1.2-4「诚实优先于叙事」。

### 4.2 AL-24 所需权限提示（高）

- **方案 A（总纲优先）**：新增 P0-23；能力契约加 `permissions[]`（取插件 `required_capabilities`）；推荐卡与工作台起单前展示；未授权阻断。
  - 利：一次兑现 §4.1 + §4.5，复用已建入口；契约加性变更不破坏端点基线。
  - 弊：M 级；文案须过禁词门禁。
- **方案 B（留 P1）**：仅记录待办。
  - 利：不占 V1.0 资源。
  - 弊：D-17 明确要求「输入 + 权限」两项，只交一半等于裁决可打折。
- **裁决：A**。依据：charter:114/149。

### 4.3 AL-30 判权验收（高）

- **方案 A（总纲优先）**：AC-13 增判据⑥（持合法令牌直取他租户对象 id → 20003/404）与⑦（列表不含他租户对象）；全端点做一次「按对象 id 直取」扫描并标注。
  - 利：把参数级验收升为对象级，封住已实测越权。
  - 弊：须先修 SEC-01（M）；扫描可能暴露更多同类缺口。
- **方案 B（维持五条）**：已全绿，不动。
  - 利：零成本。
  - 弊：「通过」会被误读为隔离完备，实测反证已成立。
- **裁决：A**。依据：charter:369 + §13 原则八。

### 4.4 AL-27 PRD 滞后（中高）

- **方案 A（回填）**：把 `/capabilities/recommend`、`/stats/tasks` 与权限提示回填为 P0-23/P0-24，附录 B 补追溯；`prd-w1-*.md` 降为增量记录。
  - 利：L1 恢复唯一需求真源，D-15/D-17 产物有归属。
  - 弊：需与 W1 PRD 去重（S）。
- **方案 B（双轨并行）**：PRD 与 W1 增量各说各话。
  - 利：零改动。
  - 弊：需求真源分裂，后续验收无锚点。
- **裁决：A**。依据：D-09 层级。

### 4.5 AL-21 Dify 版本（中）

- **方案 A（按事实）**：PRD/plan 改「Dify 社区版（Apache-2.0，`dify-api:1.17.1`）」，「是否引入商业版」单列 Open Question。
  - 利：与镜像事实、AC-11 口径自洽；避免离线分发授权风险。
  - 弊：若确需商业版将重开评估。
- **方案 B（保留「企业版」为目标形态）**。
  - 利：零改。
  - 弊：与部署事实冲突，属 AL-05 同类事实错误。
- **裁决：A**。依据：charter:409-415 + §7.1 + §9.5 成本原则。

### 4.6 AL-18 隐私合规（中，未闭合）

- **方案 A（补齐五件套）**：P0-16 扩为「使用文档 + 部署运维 + 隐私政策 + DPA 模板 + 安全白皮书 + 外部模型数据处理告知」，AC-16 同步。
  - 利：关闭 D-22 悬空决策，解私有化采购卡点。
  - 弊：法务 1-2 周；DPA 须以真实模型清单为准。
- **方案 B（延后 V1.x）**。
  - 利：不占窗口。
  - 弊：D-22 已拍板不执行＝决策失效；§10.4 是基础能力。
- **裁决：A**。依据：D-22 + charter:383。

### 4.7 AL-28 演示徽标（中）

- **方案 A（恢复徽标 + 不引导）**：推荐卡显示「演示」；demo 工具仍隐藏「发起连接」。
  - 利：同时满足 §11 与 v1.1「不引导」初衷，两者不互斥。
  - 弊：推翻 v1.1 一条已拍板修订。
- **方案 B（维持无徽标）**。
  - 利：演示无干扰。
  - 弊：用户把 demo 当可用，与原则 1、§11 直接冲突。
- **裁决：A**。依据：charter:135/415 + PRD:61-63。

### 4.8 AL-29 覆盖率口径（中）

- **方案 A（统一 85%）**：P0-22 改 ≥85%，新增 AC-22「实测 ≥85% 且 coverage/junit 产物入库」，adapter README 同步。
  - 利：单一门槛 + 有证据；与 CI 一致。
  - 弊：当前 83.52% 即自认不达标（诚实代价）。
- **方案 B（保持 80%）**。
  - 利：账面达标。
  - 弊：与 CI 冲突，CI 永红。
- **裁决：A**。依据：charter:389 + §11。

### 4.9 AL-25 计划/编排（中）

- **方案 A（V1.0 补平台侧计划生成 P0-25）**。
  - 利：贴 §4.3 字面。
  - 弊：M-L，与止血抢资源，回归面大。
- **方案 B（显式不做）**：PRD §八增非目标「不做平台侧自主计划生成，仅执行插件预定义步骤」，P1 立项。
  - 利：符合 charter:133「逐步完善」，保住止血资源。
  - 弊：§4.3 只兑现状态/失败/重试/确认四项。
- **裁决：B**。依据：charter:133 未要求 V1.0 齐备 + 原则七。
