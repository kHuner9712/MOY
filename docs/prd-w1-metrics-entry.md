## 1. 切片 A：工作流任务统计（M1/M3/M4/M5）

### 1.1 范围

- 后端 `GET /api/v1/stats/tasks?range=7d\|30d`（`range` 缺省 7d；鉴权复用既有登录上下文——与任务列表等既有端点一致的 `get_request_context`，**不扩权限矩阵**，已核实代码 16 个业务权限点无 `task:read`；文件清单见 tech-options §2.4.3）。
- 前端工作流页（`(main)/workflows/page.tsx`）表格上方 4 张指标卡。
- 统计域：**仅 `plugin_task`（工作流任务域）**，不含对话/文档。

### 1.2 指标口径（卡片 ↔ 字段 ↔ 分子分母）

| 卡片标题（对外文案，禁简写） | 指标 | 响应字段 | 分子 | 分母 |
| --- | --- | --- | --- | --- |
| 工作流任务完成率 | M1 | `completion_rate` | `COUNT(status='completed')` | 终态任务剔除用户主动取消（`cancel_requested=true`）；期末仍 `running/queued/waiting_confirm` 按未完成计入 |
| 工作流任务平均完成时长 | M3 | `avg_duration_seconds` | Σ(`finished_at − started_at`) | `completed` 任务数 |
| 工作流任务重复使用率 | M4 | `repeat_user_rate` | 窗口内同一 `plugin_id` 发起 ≥2 次的去重用户数（剔 `trigger_type='retry'`） | 窗口内发起 ≥1 次的去重用户数 |
| 工作流任务单位成功用量 | M5 | `units_per_success` | Σ(`usage_units`)（仅 `completed`） | `completed` 任务数 |

必返辅助字段（小样本判定与样本量标注用）：`total`、`completed`、`failed`、`cancelled`、`active_users`、`p50_duration_seconds`。

> **M3 口径注记（v1.1，按架构实测修订）**：`avg_duration_seconds` 为**任务总时长（含人工确认等待）**。`waiting_confirm` 停留在 schema 中无落点（`_pause_for_confirm` 只改 status，无进入/退出时间戳），MVP **不扣除**等待时长，卡片与文档不得宣称「已扣除等待」；「扣除等待」需新增列 → 独立迁移立项，随 `metrics-definition-v1.0.md` v1.1 修订 M3。

### 1.3 口径红线（验收一票否决）

| # | 红线 |
| --- | --- |
| R1 | 指标名对外必须写「**工作流任务**××」，禁简写「任务完成率」；与 `/model/usage`（对话/文档域）**不是同一套，不可混算**、不可合并为单一百分比（指标文档 §1.5），两口径须并列说明 |
| R2 | `total < 10` 时前端显示「**样本还少，仅供参考**」+ 样本量；**禁用占位词**（暂不支持/开发中/即将上线/敬请期待） |
| R3 | `plugin_task` ≠ 全部使用量，看板/卡片标题必须带「工作流任务」限定词 |
| R4 | 无数据时接口返回 **0，不得 NaN/null**；界面禁现技术字段名（units/token 等），用业务语言 |

### 1.4 验收（AC-A）

| # | 条款 | 判据 |
| --- | --- | --- |
| AC-A1 | 接口契约 | `range` 缺省 7d；`range=7d\|30d` 返回 §1.2 全部字段；`range` 非法 → **20001**（PARAM_INVALID），不得 500 |
| AC-A2 | 分子分母可复算 | 造数（含用户主动取消、`waiting_confirm` 跨期、`retry_of` 各 1 条）后接口值与 §1.2 公式手工复算一致（`waiting_confirm` 任务计入 M3 总时长、按未完成计入 M1 分母）；`test_stats_tasks.py` 落地 |
| AC-A3 | 空数据 | 空租户全指标返回 0，无 NaN/null |
| AC-A4 | 小样本 | `total<10` 时卡片显示「样本还少，仅供参考」+ 样本量；占位词扫描 0 命中 |
| AC-A5 | 口径隔离 | 工作流页与 `/model/usage` 并列处均带数据域限定词；两域数字不进同一百分比 |
| AC-A6 | M4 窗口 | `range=30d` 符合 M4 定义（30 天窗口、剔 retry）；`range=7d` 为同公式 7 天窗口，卡片须标注统计期 |
| AC-A7 | 双后端 | 内存/PG 双实现结果一致（PG 走 `idx_task_status_time`） |
| AC-A8 | 门禁 | `validate_openapi.py` 通过；`npm run scan:pages` 通过（工作流页加载/空/错误三态齐全） |

### 1.5 切片 A 不做什么

不落 `artifact_adoption` 表（M2 采纳率，独立批次）｜不改 `/ops/metrics` 运营看板｜不建成本系数表、不出「每任务 X 元」（M5 完整口径需外部单价，本切片只出「单位成功任务用量」相对值）｜不修 `usage_event.units` 折算口径｜不新增 `waiting_confirm` 时长列（「扣除等待」独立迁移立项）｜不做 M6/M7/M8。

## 2. 切片 B：统一任务入口 MVP（总纲 §4.1）

### 2.1 范围

- 后端 `GET /api/v1/capabilities/recommend?goal=…&limit=3`：规则推荐 Top3 + 命中理由；`limit` **缺省 3、上限 10**；空 `goal` 返回能力目录（不报错）。
- 前端对话页顶部「目标式发起」输入框 + 推荐卡；「开始」→ `/workbench/{pluginId}?goal=…`；工作台读 `?goal=` 预填首个文本输入并随任务提交。
- **复用 `POST /api/v1/agent/tasks` 现有 `goal` 字段（≤4000 字），不改接口契约。**

### 2.2 匹配规则（可枚举、可测）

| 项 | 规则 |
| --- | --- |
| 料源 | 6 个插件声明（`name/summary/description/category/inputs[].label`）+ 5 款工具注册表（`display_name/category/operations[].display_name`） |
| 打分 | `goal` 中文 2-gram + 关键词表 → 命中 `name(×3)/summary(×2)/category(×1)/inputs.label(×1)` → Top3 |
| 理由回填 | 每张卡展示命中词 + 来源字段（用户看得到「为什么给我这个」） |
| 徽标 | 工具推荐卡 MVP **不带**「演示」徽标（目录服务不耦合连接器常量 `INTEGRATION_STATUS`）；徽标统一随 V1.1 连接器真实化批次 |
| 不引入 | 无模型、无语义检索、不新建「能力」表（目录实时组装，避免第三份真相） |

### 2.3 边界（必须写明）

1. **规则匹配，不引入模型**——可解释、可测试、可离线；语义检索留 V1.1，接口签名不变。
2. 推荐理由必须回填，否则等于换了个搜索框。
3. 复用现有 `goal` 字段，**不改 `POST /api/v1/agent/tasks` 契约**。
4. 6 插件/5 工具的匹配规则可枚举、可单测。

### 2.4 验收（AC-B）

| # | 条款 | 判据 |
| --- | --- | --- |
| AC-B1 | 推荐正确性 | 各类目标命中正确插件、易混词不串（`test_capability_recommend.py` 12 条用例） |
| AC-B2 | 理由回填 | 每张卡展示命中理由，禁空理由 |
| AC-B3 | 无匹配兜底 | 无命中时返回**能力目录前 N 条 + 引导文案**（换种说法 / 去插件市场浏览，落点 `(main)/plugins` 页），不得空列表、不得占位词 |
| AC-B4 | 空目标 | `goal` 为空 → 返回目录，不报错 |
| AC-B5 | 参数边界 | `goal` 超 4000 字、`limit` <1 或 >10 → 20001；`limit` 缺省 3 |
| AC-B6 | 跳转契约 | 「开始」→ `/workbench/{pluginId}?goal=…`；工作台预填并随任务提交；无新增/修改后端字段 |
| AC-B7 | 所需输入提示 | 推荐卡展示该插件 `inputs`（要准备什么），兑现 D-17「所需输入提示」 |
| AC-B8 | 门禁 | `scan:pages`（对话页三态齐全）、禁词/占位词扫描 0 命中 |
