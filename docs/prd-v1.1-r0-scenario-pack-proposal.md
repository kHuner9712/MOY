| 依据 | 总纲 §5.1/§5.2/§6.1；ADR-0005 D-11（PRD 补 R0）；对齐报告 AL-03、LED-002/003 |

**设计约束**：① 不引入组织概念（需"管理员开启"的能力一律不进 R0 主路径）；② 不做成插件市场新增分类——R0 要的是目标式入口 + 轻模板，不是再装一个工作台；③ 只复用现有能力，不新建平台模块；④ 现有 5 个连接器全桩且均为办公类，**平台当前没有任何检索能力**，涉及联网检索的场景必须降级。

## A. 资料整理（最低成本、最可能先做）

- **输入**：3-20 份本地文件 + 一句话目标（如"整理成一份竞品对比"）。
- **步骤**：批量上传 → 切分与索引进度 → 按主题聚类去重 → 生成目录与摘要 → 每条结论标注来源文件与片段。
- **产物**：结构化 md/docx（目录 + 分主题摘要 + 来源引用），可选对照表。
- **所需能力**：知识库/RAG（L2 已有）、附件上传（已有）、引用溯源（已有）、file 产物导出（已有）；**缺口：批量上传体验与对照表产物**。
- **V1.1 最小可用**：单次 ≤10 份、产物 md + 复制/下载；不做跨知识库合并。

## B. 研究综述（**有真实缺口，必须写明边界**）

- **输入**：一个主题（可选：自备文献包）。
- **步骤**：主题澄清（1-2 轮追问收敛）→ 检索 → 筛选去重 → 分主题归纳 → 输出带引用综述 → 显式标出"证据不足"。
- **产物**：综述文档（研究问题 / 现状 / 分歧点 / 证据强度 / 参考列表）。
- **所需能力**：RAG 与引用（L2 已有）、长文写作（已有）；**外部检索 = 缺口，且短期无法补齐**（无检索类连接器，现有 5 款均为办公类且全桩）。
- **诚实边界（必须写进任何对外材料）**：**V1.1 只做"基于用户上传资料的综述"**；"联网检索式综述"需先有可用检索连接器（并过 SSRF 白名单与合规评估），**不在本提案范围**。
- **V1.1 最小可用**：上传 ≤20 篇 → 综述 + 引用列表；证据不足显式提示，**不臆造文献**。

## C. 文档模板（最容易验证"零学习成本"）

- **输入**：选内置轻模板（5 个）+ 3-5 条要点（口语化即可）。
- **步骤**：选模板 → 表单化填要点（非自由 prompt）→ 生成 → 就地修改 → 导出。
- **产物**：保留模板结构的 md/docx。
- **所需能力**：插件声明式（L2 已有）、产物编辑 `PUT /agent/tasks/{id}/artifacts/{aid}`（已有）、file 导出（已有）、统一组件库渲染（已有）；**缺口：5 个模板的声明式配置 + 表单化输入**。
- **V1.1 最小可用**：周报/方案/README/简历/会议纪要 5 个模板，模板为配置不写代码。

**增量成本判断**：A 为 S-M（主要在体验），B 降级后 S，C 为 S——三场景均不触碰平台级模块。

**验证方式（不设数字，先建基线）**：唯一硬指标是 R0「首次任务完成率」（进入 → 拿到可用产物，无需人工提示）；不采用注册数/日活（R0 未开放，任何增长数字都是编造，违反总纲 §十四末段）。**反例检查**：若某场景必须建团队或配权限才能用，则该场景设计失败。

**明确不做**：联网检索/爬虫/学术库对接、移动端、多人协作、用户投稿模板市场、R0 专属计费（订阅结构待 Q5 决策）。
