| 字段 | 内容 |

## 三、判据偏离说明（非豁免，用于对齐 QA 用例口径）

### W-03 ｜ 跨租户 / 不存在资源的详情接口返回 `11001` 而非 `20003`

| 字段 | 内容 |
| --- | --- |
| 关联用例 | PERM-06（原判据：跨租户访问详情必须 `20003`） |
| 现状 | KB3 / KB4 对「跨租户 base_id」与「真不存在」统一返回 `11001`（知识库不存在） |
| 裁定 | **不算缺陷，判据改为「非 0 且不返回任何数据」** |
| 理由 | ① 跨租户与「真不存在」在数据层不可区分（RLS 下查不到就是查不到），强行区分需要额外存在性探测，反而制造信息泄露面；② 返回「不存在」不泄露资源是否存在，安全姿态**强于**返回「无权限」；③ KB3/KB4 的错误码在架构 §4.2 已冻结，改码会破坏 G-04 加性 diff 门禁。 |
| 仍需验证 | 响应体不得包含库名、文档名、分片内容、计数差异等可用于反推存在性的信息（QA 已验证 `test_qa_*` 中 `a7` 系列）。 |
| 适用批次 | B05 起长期有效 |
| 签字 | 齐活林 · 2026-10-22 |

### W-04 ｜ G-23 对账数据源：由「Valkey 首选」改为 `usage_event` 二次来源

| 字段 | 内容 |
| --- | --- |
| 关联门禁 | G-23（`scripts/reconcile_usage.py --period <YYYY-MM> --threshold 0.01`） |
| 原口径 | 架构草案要求对账优先读 Valkey 计数，与 `usage_event` 比对 |
| 现口径 | 对账双方改为「`usage_event` 明细求和」 vs 「`usage_daily` 聚合表」 |
| 裁定 | **批准口径变更** |
| 理由 | ① Valkey 是缓存不是账本，淘汰/重启/多副本都会让计数漂移，拿它当对账基准等于用不可靠数据校验可靠数据；② PG 的 `usage_event` 是唯一写入真相源（B07 已保证 `generation_id` 唯一），用它反查聚合表能真正发现「聚合写漏/重复聚合」；③ 多副本下 Valkey 计数天然不收敛，该口径无法通过 G-23。 |
| 影响 | 对账脚本不依赖缓存可用性，可在离线/私有化环境独立执行；偏差 >1% 仍写 `audit_log(billing.reconcile_mismatch)` |
| 适用批次 | B07 起长期有效 |
| 签字 | 齐活林 · 2026-10-22 |
