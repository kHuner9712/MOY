## 1. 架构与信任边界

### 1.1 一句话架构

平台由前端应用、业务适配层、身份服务、内容处理服务、关系数据库（含检索扩展）、缓存、插件运行服务组成，全部通过容器编排部署；对公网**只暴露一个入口端口**。

### 1.2 信任边界（4 层）

| 层 | 组件 | 信任级别 | 边界控制 |
| --- | --- | --- | --- |
| ① 公网 | 浏览器 → 入口网关 | **不可信** | 仅 1 个端口对外；其余服务不映射宿主端口 |
| ② 应用层 | 前端应用、业务适配层 | 受控 | 强制身份校验；权限默认拒绝；每请求带链路标识 |
| ③ 数据层 | 关系数据库、缓存、对象/文件存储 | 受控且最小授权 | 应用账号 `NOSUPERUSER + NOBYPASSRLS`；行级隔离策略 |
| ④ 外部服务 | 客户已连接的第三方工具、客户配置的模型服务 | **不可信（外部）** | 仅在被授权且被调用时出站；超时与错误分类统一收口 |

**证据**：
- 只暴露一个端口：`deploy/docker-compose.lite.yml`（`proxy` 服务是唯一有 `ports:` 映射的服务，其余无宿主端口映射）。
- 基础设施端口绑回环：`deploy/docker-compose.yml` 中检索服务/对象存储/监控端口均为 `127.0.0.1:...`。

### 1.3 两种部署形态的安全差异

| 维度 | 私有化（单租户） | SaaS（多租户） |
| --- | --- | --- |
| 数据边界 | 客户自有网络内，默认不出网 | 平台方云环境 |
| 隔离要求 | 环境隔离 | **行级隔离策略 + 应用层企业标识双重校验**（必需） |
| 平台方可访问性 | 不访问 | 可访问（受运维权限约束） |
| 密钥管理 | 客户自行持有 | 平台方持有（环境变量注入） |

## 2. 身份与访问控制

### 2.1 身份认证

| 项 | 实现 |
| --- | --- |
| 认证方式 | 企业统一身份（OIDC / OAuth2），`OA_AUTH_MODE=oidc` |
| 令牌校验 | `oidc` 模式下**强制验签**并校验签发方与受众；`stub` 模式仅供本地开发，**生产/预发环境启动即拒绝**（配置项为空时报 `30004` 并拒绝启动） |
| 角色来源 | 身份令牌中的角色声明（兼容顶层数组与嵌套结构两种形态） |
| 登录回跳 | 授权码与一次性随机值**不进入 Referer**（该页响应头单独设置 `Referrer-Policy: no-referrer`） |

**证据**：`apps/adapter/app/core/security.py`（验签、签发方/受众校验、生产环境强制 `oidc`）；`apps/web/next.config.js`（`/auth/callback` 单独 `no-referrer`）。

### 2.2 权限模型：两层判定

```
第一层 权限点（角色 → 权限点矩阵）
   └─ 16 个业务权限点 + 4 个运营权限点 = 20 个已登记权限点
第二层 对象级（同一个人能看到哪些具体资料）
   └─ 知识库可见范围（全企业 / 仅自己 / 指定成员）
```

两层都通过才放行。**只有权限点没有对象授权，仍然看不到具体资料。**

**证据**：`apps/adapter/app/core/builtin_roles.py`（4 个内置角色 + 20 个权限点的唯一实现）；`apps/adapter/app/schemas/rag.py`（可见范围三值枚举）。

### 2.3 默认拒绝（fail-closed）与仅 2 条例外

这是本产品访问控制最重要的一条纪律：

- **无角色声明 → 一律拒绝**（返回 `20003`"当前账号没有该操作的权限"），不做任何"默认放行"猜测；
- 仅 **2 条**经过登记的对象级判定例外（白名单锁定在 `docs/security/permission-whitelist.lock`）：

| 编号 | 权限点 | 方法 | 为什么必须例外 |
| --- | --- | --- | --- |
| W-1 | `knowledge:base:read` | `GET` | 知识库可见性是对象级判定（逐库按授权与可见范围过滤），角色矩阵无法表达；普通成员本就没有该权限点，在此拒绝会让成员连自己建的库都看不见 |
| W-2 | `tool:connection:manage` | `GET` | 单条工具调用记录能否可见，取决于该连接是否属于调用者本人（对象级）；**只放开 GET，写操作仍走矩阵** |

白名单有**锁定文件 + 自动化断言**：任何人新增一条延迟判权分支，测试即红。

**证据**：`docs/security/permission-whitelist.lock`（2 条，带理由）；`apps/adapter/tests/security/test_permission_fail_closed.py`（9 条用例）。

### 2.4 多租户隔离（SaaS 形态的关键控制）

| 控制 | 实现 |
| --- | --- |
| 数据库层 | 每张业务表挂行级隔离策略：`tenant_id = current_setting('app.tenant_id')`；**未设置企业标识时表达式为空，查询返回 0 行**（不是返回全部） |
| 应用层 | 每个请求从令牌解析企业标识，并在事务内显式设置；业务代码不允许自行拼接企业条件 |
| 数据库账号 | 应用账号 `NOSUPERUSER + NOBYPASSRLS`（**行级策略对其生效**；超级用户会绕过策略，所以绝不让应用使用超级用户） |
| 平台目录数据 | 平台级共享数据用独立策略（`__platform__` 标识），与租户数据分离 |
| 审计表 | 应用账号对操作记录表 `REVOKE UPDATE, DELETE`（数据库权限级"只增不改"） |

**证据**：`deploy/init-schema-phase2.sql`（策略创建，含 `current_setting('app.tenant_id')`）；`deploy/init-app-role.sql`（`NOSUPERUSER + NOBYPASSRLS`，第 67 行 `REVOKE UPDATE, DELETE ON audit_log`）。

**可复现的验证方式**（客户测试环境）：
```bash
# 未设置企业标识 → 应返回 0 行
psql "$OA_DATABASE_URL" -c "SELECT count(*) FROM conversation;"
# 设置企业标识后 → 返回本企业行数
psql "$OA_DATABASE_URL" -c "SET app.tenant_id='<企业标识>'; SELECT count(*) FROM conversation;"
```

### 2.5 角色矩阵（4 个内置角色 + 平台运营角色）

| 角色 | 权限点数量 | 说明 |
| --- | --- | --- |
| 企业所有者 `owner` | 全部 16 个业务权限点 | 唯一可执行"导出/删除企业数据" |
| 组织管理员 `org_admin` | 全部 16 个业务权限点 | 不能执行全企业删除 |
| 普通成员 `member` | 9 个 | 可以建库、上传、连工具；不能管人、不能管授权 |
| 访客 `guest` | 3 个 | 只读为主 |
| 平台运营 `ops_operator` | 4 个运营权限点 | 仅运营后台，不能触碰客户业务数据 |

**证据**：`apps/adapter/app/core/builtin_roles.py`。

### 2.6 防滥用

| 控制 | 默认值 | 实现 |
| --- | --- | --- |
| 请求频率保护 | 每人每分钟 120 次 | 缓存后端计数（`OA_RATELIMIT_ENABLED`） |
| 幂等保护 | 24 小时 | 相同幂等键的重复提交返回"重复的请求已被忽略"，不重复扣额度、不重复建单 |
| 上传大小上限 | 50 MB | 后端与网关配置**必须一致**（不一致会出现纯文本 413 或白走一趟） |
| 额度硬止损 | 100% 即拒 | 对话类请求在调用外部服务**之前**判定，超额时外部调用次数为 0 |

**证据**：`deploy/.env.lite.example`（`OA_RATELIMIT_*`、`OA_IDEMPOTENCY_*`、`OA_MAX_UPLOAD_BYTES`）；`deploy/nginx/lite.conf`（`client_max_body_size`）。

## 3. 数据保护

### 3.1 传输加密

| 链路 | 措施 |
| --- | --- |
| 浏览器 ↔ 平台 | HTTPS/TLS（由客户前置网关或负载均衡终止证书）；下发 `Strict-Transport-Security: max-age=31536000; includeSubDomains` |
| 平台内部服务间 | 编排内网；不映射宿主端口；跨服务调用不经公网 |
| 平台 ↔ 外部服务 | 出站按客户网络策略约束（私有化形态默认不出网） |

### 3.2 静态加密与凭据保护

| 对象 | 保护方式 |
| --- | --- |
| 第三方工具授权凭证（邮箱/仓库/企微/飞书/公众号） | **AES-256-GCM** 加密存储；12 字节随机 nonce；密文含 16 字节认证标签；同一明文每次加密结果不同 |
| 密钥来源 | 环境变量注入（32 字节 base64）；**缺失时真实部署形态启动即失败**（`30004`），不静默降级 |
| 密钥轮换 | 旧密钥挪到"轮换期旧密钥"配置（按版本号选用），新写入一律用新密钥，旧密文仍可解；全部重加密完成后再移除旧密钥 |
| 明文生命周期 | 仅在进程内存存活一个请求的生命周期；不落日志、不进响应、不进缓存 |
| 数据库口令 | 安装时随机生成（`openssl rand -hex 24`），写入客户环境的配置文件（权限由客户系统管理） |
| 产物下载 | 短期有效令牌（`/files/artifacts/<下载令牌>`），非永久公开链接 |

**证据**：`apps/adapter/app/core/crypto.py`（算法、nonce、密钥版本口径、轮换步骤、生成命令提示）；`apps/adapter/app/core/artifact_token.py`（下载令牌）。

**轮换操作**：见《密钥轮换清单》（`docs/key-rotation-checklist.md`）。

### 3.3 数据最小化（已实现的具体承诺）

| 承诺 | 实现 |
| --- | --- |
| 不保存上传文档的原始字节 | 上传路径为"内容 → 提交解析"一次调用，业务表只存文件名、大小、内容摘要值、页/段数量与处理状态 |
| 敏感信息不进入记忆 | 进入写入路径前即过滤：身份证号、银行卡号、手机号、密码/密钥/令牌类字样、健康与宗教类信息；命中即丢弃，**且不记录匹配到的原文** |
| 日志不含正文与凭证 | 应用日志只记路径、状态码、耗时、错误分类、链路标识 |
| 指标不含个人标识 | 指标标签只允许有限枚举（方法、路径模板、状态分类、能力类型等）；**明确禁止**企业标识、用户标识、会话标识等作为标签 |

**证据**：`apps/adapter/app/services/memory_extractor.py`（敏感信息正则，含"数字类模式不能用词边界"的踩坑注释）；`apps/adapter/app/core/metrics.py`（`ALLOWED_LABELS` / `FORBIDDEN_LABELS`，含断言测试）。

### 3.4 数据权利能力（导出与删除）

| 能力 | 实现要点 |
| --- | --- |
| 全企业导出 | 五类数据分别导出为结构化文本 + 清单文件（每个文件行数与摘要）；单次上限 20 万行，**超限明确报错不截断**；下载地址短期有效；仅企业所有者可执行 |
| 全企业删除 | 两段式：先停用企业**阻断后续写入**，再分批（每批 1000 行）硬删除，避免长锁；出具**删除证明**（各表行数 + 时间戳 + 需 DBA 单独清理的操作记录条数） |
| 操作记录 | 应用账号无删除权限，需客户 DBA 按脚本执行；应用侧清理任务会逐字输出 `audit_log=skipped(no privilege)` 作为"知道自己没权限"的证据 |
| 单人粒度 | 使用者可删单条记忆、按类清空、删除会话（软删除 30 天可恢复） |

**证据**：`apps/adapter/app/business/tenant_data_service.py`（两段式删除、证明、上限与不截断口径）；`apps/adapter/app/api/v1/tenant_data.py`（仅所有者可删、逐字输入企业名称二次确认）；`sql/retention-audit.sql`。

## 4. 应用安全

### 4.1 已启用的安全响应头

由前端应用统一下发（`apps/web/next.config.js` 的 `headers()`）：

| 响应头 | 值 | 作用 |
| --- | --- | --- |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | 强制 HTTPS，消除首跳被降级窗口 |
| `Content-Security-Policy` | 见 4.2（**含当前取舍**） | 限制脚本/样式/连接来源，防注入 |
| `X-Frame-Options` | `DENY` | 防点击劫持（与 CSP `frame-ancestors 'none'` 双声明，兼容旧浏览器） |
| `X-Content-Type-Options` | `nosniff` | 防 MIME 嗅探 |
| `Referrer-Policy` | `strict-origin-when-cross-origin`（登录回跳页 `no-referrer`） | 防止路径与授权参数外泄 |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | 显式关闭产品不需要的浏览器能力 |

### 4.2 内容安全策略的当前取舍（**如实披露**）

```
default-src 'self';
script-src 'self' 'unsafe-inline';
style-src 'self' 'unsafe-inline';
img-src 'self' data: https:;
font-src 'self' data:;
connect-src 'self' http: https:;
object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

| 项 | 当前值 | 为什么这么取 | 风险与后续 |
| --- | --- | --- | --- |
| `script-src` | 含 `'unsafe-inline'` | 前端框架的服务端渲染载荷以内联脚本注入，纯 `'self'` 会让首帧白屏且只报一条难以归因的策略违规 | 削弱了内联脚本注入的防护。**后续计划**改为逐请求随机数（nonce）方案，去掉 `'unsafe-inline'` |
| `connect-src` | 放开 `http:` 与 `https:` | 私有化现场常见"前端与业务服务不同源、且只有 HTTP"，收紧会直接打断登录 | 出站目标不受策略限制。**后续计划**改为部署时注入具体来源白名单 |
| `style-src` | 含 `'unsafe-inline'` | 组件库运行时注入样式 | 样式注入风险低于脚本，暂保留 |
| `img-src` | `data:` + `https:` | 内联图标与外部头像/预览 | 可接受 |

### 4.3 其它应用层控制

| 控制 | 实现 |
| --- | --- |
| 跨域 | 生产环境跨域白名单为**空**（同源部署无跨域需求）；仅开发环境放开本机前端端口。历史上"通配符 + 携带凭据"的错误组合已修正 |
| 错误信息 | 对外只返回业务文案；内部细节只进日志，不暴露组件名、库名、堆栈、异常类名 |
| 请求追踪 | 每请求注入链路标识（响应头 `X-Trace-Id`），日志与错误响应可关联 |
| 上传限制 | 后端与网关上限一致（50 MB）；请求体超限返回业务文案 |
| 任务防重 | 任务推进使用数据库级互斥锁，两个进程同时推进时步骤序号只加 1 |

**证据**：`apps/adapter/app/main.py`（跨域白名单逻辑与历史问题注释）；`apps/adapter/app/core/errors.py`（对外文案与内部细节分离）。

## 5. 审计与可观测

### 5.1 操作记录（审计）

| 项 | 说明 |
| --- | --- |
| 记录内容 | 操作者、角色、动作名称、对象类型与标识、结果、**掩码后的 IP**、链路标识、变更摘要、发生时间 |
| 不可篡改性 | 应用账号对审计表 `REVOKE UPDATE, DELETE`——**数据库权限级**的"只增不改"，不依赖应用自觉 |
| 保留期 | 180 天（可配置）；到期由客户 DBA 执行 `sql/retention-audit.sql` |
| 查询 | 具备"查看操作记录"权限的角色可在产品内查询 |

### 5.2 指标（15 条）与标签纪律

| 项 | 说明 |
| --- | --- |
| 指标数量 | 15 条（请求量、延迟直方图、错误分类、任务队列深度、预算使用比例等） |
| 标签白名单 | 12 个允许标签；**7 类个人/资源标识被明确禁止**（企业、用户、会话、消息、任务、记忆、作业） |
| 抓取开销 | 指标端点只渲染内存数据，**不在抓取时查库**——避免监控把数据库持续打醒 |
| 交付形态区分 | 部署形态作为外部标签注入，同一套看板可区分交付形态 |

**证据**：`apps/adapter/app/core/metrics.py`（`ALLOWED_LABELS`、`FORBIDDEN_LABELS`、`STATUS_CLASSES` 与断言测试）。

### 5.3 告警（5 条）

| 告警 | 条件 | 级别 |
| --- | --- | --- |
| 接口 5xx 占比过高 | 2 分钟窗口内 5xx 占比 > 5%，持续 2 分钟（实际约 4 分钟触发） | critical |
| 接口 P95 延迟过高 | P95 > 3 秒（**已排除流式路由**：流式时长取决于回答长度，纳入会长期误报） | warning |
| 后台任务积压 | 队列深度 > 50，持续 5 分钟 | warning |
| 租户预算接近上限 | 预算使用比例 > 0.8，持续 10 分钟（仅私有化形态注册该指标） | warning |
| 抓取目标失联 | 任一目标连续 2 分钟抓取失败 | critical |

**证据**：`deploy/alert.rules.yml`（5 条规则，含"为什么不要为了对齐 2 分钟去改表达式"的说明）；`deploy/prometheus.yml`（4 个抓取目标）。

## 6. 安全测试

### 6.1 自动化安全用例

| 项 | 内容 |
| --- | --- |
| 运行方式 | `pytest -m security`（在 `apps/adapter/` 目录下执行） |
| 覆盖的攻击面（5 类） | ① 认证绕过 ② 跨租户越权 ③ 对象级越权 ④ 额度滥用 ⑤ 信息泄露 |
| 补充域（2 类） | ⑥ 权限失败关闭（含白名单锁定断言） ⑦ 租户伪装（伪造企业标识） |

## 7. 供应链与交付完整性

| 项 | 措施 |
| --- | --- |
| 组件清单（SBOM） | 四层：Python 依赖 / 前端依赖 / 容器镜像（含指纹）/ 离线插件包；每层均有非空断言 |

| 离线包完整性 | 逐文件 SHA-256 清单（`sha256sum -c`）+ 镜像指纹逐项核对；两者都过才算"包是对的" |

| 许可合规 | 第三方组件许可声明；`.difypkg` 离线包做许可扫描（正样本通过、负样本必须报错的可红证明） |

## 8. 已知边界与后续计划（诚实清单）

> 这一章是本文档最重要的部分。**下面每一条都是真实存在的限制**，不要因为"看起来不严重"就删掉——客户的安全评审会自己发现它们。

| # | 已知边界 | 影响 | 当前缓解 | 后续计划 |
| --- | --- | --- | --- | --- |
| S-1 | 内容安全策略的 `script-src` 含 `'unsafe-inline'` | 削弱对内联脚本注入的防护 | 无内联用户内容渲染；输出统一转义 | 改用逐请求随机数方案（nonce），去掉 `'unsafe-inline'` |
| S-2 | `connect-src` 放开 `http:`/`https:` | 出站目标不受策略限制 | 依赖网络层出站策略 | 部署时注入具体来源白名单 |
| S-3 | 安全响应头由**前端应用**下发，**入口网关未注入** | 纯接口响应与静态资源不带全套安全头 | 接口响应为结构化数据，浏览器不渲染 | 在网关层统一下发（含 HSTS），覆盖所有响应 |
| S-4 | 令牌签名使用对称算法（HS256） | 签发与校验共用同一密钥，泄露影响面较大 | 密钥仅存于服务端配置；支持轮换 | 评估非对称算法（RS256/ES256）迁移方案 |
| S-5 | 未内置多因素认证（MFA） | 账号安全依赖客户身份系统 | 通过统一身份接入，可复用客户既有 MFA | 由客户身份系统提供；产品侧不重复建设 |
| S-6 | 密钥托管在配置文件/编排注入，未接外部密钥管理服务 | 密钥保护强度取决于宿主安全 | 文件权限由客户系统控制；支持轮换与旧密钥过渡 | 支持对接客户 KMS/Vault |
| S-7 | 审计记录为"只增不改"，但**没有做外部不可篡改存储或哈希链** | 拥有数据库超级用户权限的人仍可篡改历史记录 | 应用账号无权限；审计表独立 | 评估日志外送与哈希链方案 |
| S-8 | 未做第三方渗透测试报告 | 客户安全评审缺少外部背书 | 自查覆盖 5 类攻击面 + 2 个补充域共 **58 条**自动化用例；有可红证明 | 计划在 V1.1 前安排一次第三方渗透测试 |
| S-9 | 无内置 WAF/机器人防护 | 大规模自动化攻击需依赖网关侧防护 | 频率保护、幂等保护、额度硬止损 | 建议客户在网关侧启用 WAF（部署手册有说明） |
| S-10 | 日志脱敏依赖结构化字段约定，**未做全文敏感信息扫描** | 若业务代码误把敏感内容写进日志字段，不会被自动拦截 | 日志字段白名单；代码评审 | 增加日志侧敏感信息扫描 |
| S-11 | 轻量版不含代码沙箱 | 某些工作流的"代码执行"节点不可用 | 属功能限制，安全上是正向 | 按客户需求提供全量版编排 |
| S-12 | 轻量版不含统一出站代理 | 出站控制依赖客户网络策略 | 私有化默认不出网 | 由客户网络安全策略承担（这是更真实的边界） |
| S-13 | 操作记录保留期清理需 DBA 手工执行 | 清理不及时会导致保留期超期 | 清理任务逐字输出"无权限跳过"作为证据；部署手册有季度清单 | 评估赋予专用清理角色（需评审"只增不改"约束） |
| S-14 | 备份中不做逐条删除 | 备份中的历史副本会随轮换自然过期 | 备份保留期默认有限（7/30/90 天，按客户策略） | 与客户约定备份保留期上限 |

### 8.1 本版本**不做**的事（明确划出边界）

1. 不做"承诺式合规认证"——本白皮书陈述实现，不替代等保测评/ISO 认证报告；
2. 不内置数据分类分级引擎（依赖客户自行定义资料可见范围）；
3. 不提供终端防护（DLP/水印）能力；
4. 不代客户管理其身份系统的口令策略与账号生命周期。
