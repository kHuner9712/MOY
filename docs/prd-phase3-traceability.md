## 0. 使用说明

1. **用例编号规则**：`TC-P3-xx` 与 P0 编号 1:1 对应（`P0-P3-01` → `TC-P3-01`）。单条 P0 的断言用 `a/b/c/d/e` 后缀，可直接落成一个用例的多个 assert（或拆成同编号多个用例，**编号不得跳号**）。
2. **断言写法约定**：每条断言必须是「动作 → 可观测结果 → 期望值」三段式，禁止出现「体验良好」「提示合理」这类不可判定表述。可观测对象只有五类：HTTP 响应字段、页面 DOM 文案/属性、仓库或第三方回执、导出文件内容、扫描脚本退出码。
3. **三档标记**（每条断言末尾标注）：
   - `A` = 可自动化（脚本/接口断言/静态扫描，建议进 CI）；
   - `M` = 需人工执行（跨系统核对、文件打开、走查）；
   - `A+M` = 接口断言可自动化 + 结果物需人工抽验。
4. **前置数据约定**：凡涉及真实第三方的断言，前置条件统一为「沙箱环境 + 契约桩」（见第 5 章表四），无法提供的必须标 `M` 并留证。
5. **本文所有体积类数字均标口径**（2026-10-23 补，源于「同一数字四种结果」事故）：行数 = `wc -l` 口径；断言数 = 按 `；①…⑨` 编号项计数口径；端点数 = 附录 A.1 表格行口径；P0 条数 = PRD §3.1 表格行口径。**引用时不写口径的数字不要用**——604/603/606/607 四种结果没有一个是错的，全差在文末换行。另：**行数还依赖读取时刻**，跨文档对表时建议标采样点（如 `606 行 @ v1.2 封版后`），否则两个都对的核算（如架构 1495 与 1502）会被误判为不一致。
6. 本文件**不含错误码数值**：错误码由架构统一分配后回填，QA 写用例时用「语义名」占位（如 `E-4 未授权`），码值落地后由架构提供映射表一次性替换。

### 3.4 Offer 金额扫描三规则（QA 直接抄）

- **R1（带单位金额）**：`(?<!\d)(?:[1-9]\d{0,2}(?:,\d{3})+|\d{3,})(?:\.\d{1,2})?\s*(?:元|万元|万|k|K|/月|每月|/年|年薪)`
- **R2（金额上下文内的裸数字）**：在 `薪|工资|待遇|补贴|奖金|年终|期权|股权|月收入|总包` 前后 **±20 字符**窗口内，匹配 `(?<![\d-])\d{3,7}(?:\.\d{1,2})?(?![\d-])`
- **R3（金额位置的禁用表述，主理人 2026-10-23 追加）**：金额位置**只允许两种取值**——**空字符串** 或 **「按公司标准执行」**；以下表述**不算合规**（等于把金额决策甩给用户，且用户会误以为结论是模型给的）：`面议|待定|可谈|可议|根据经验|视情况|依能力|面谈|另议|按市场水平`。校验方式：对 Offer 的三个金额字段值 + 该产物全文，跑 `(面议|待定|可谈|可议|根据经验|视情况|依能力|面谈|另议|按市场水平)` → **0 命中**；同时断言字段值为 `""` 或 `"按公司标准执行"`（二者之一）。
- **⚠ 三条规则的作用域（架构 2026-10-23 发现，必须照此实现）**：R1/R2/R3 **只扫 `output_key=offer` 这一个产物**（含其三个金额字段值），**不扫任务的全部产物**。原因：`screening`（简历筛选）产物的 `conclusion` 枚举**合法包含「待定」**（P0-P3-21），若拿整个任务的产物跑 R3，**每份「待定」简历都会误报成 P0 缺陷**。QA 写用例时必须把扫描对象固定为 offer 产物；扫描范围一旦放到"任务级"，这条判据立即失效（全是假红，且方向是"看起来更严"，最容易被当成好事放过）。
- **豁免规则**（避免误伤，用例输入需可复现）：日期 `\d{4}-\d{1,2}-\d{1,2}`、工号/编号类（形如 `EMP-1234`）、百分比 `\d+(\.\d+)?%`、试用期 `\d+\s*个月`、办公电话。**豁免项必须固化在 QA 用例数据表中（单列「豁免项」，与用例编号同行）**，验收时不得临场解释、不得临时新增豁免。
- **通过标准**：R1 命中 0 **且** R2 命中 0 **且** R3 命中 0 **且** 字段取值在白名单内；任一不满足即为 P0 缺陷（违反「AI 不得生成任何金额」的合规约束）。

**两条门禁口径（2026-10-23 由 B16 实跑暴露后补，架构已落 §10/§11）**

1. **隔离复跑必须显式定位被测树**：扫描类门禁（`validate_plugins.py` / `validate_plugin_actions.py` / `validate_capability_usage.py`）**不带 `--dir` 时会扫"已安装包路径"而非脚本所在树**，导致"隔离复跑"实为验错树。故：B16 起每批复跑一律带 `--dir <git archive 归档目录>`，并在批次报告固定记录「**扫描绝对路径 + 归档 sha**」两列，**缺两列则该批门禁结论无效**；若门禁做 `manifest_sha256` 比对，**必须复用加载器的唯一入口 `manifest_digest()`**：对**解析后的声明对象**做规范 JSON（`sort_keys=True` + 紧凑分隔 + `ensure_ascii=False`）再取 sha256，**不基于原始字节**——这样 CRLF / BOM / 尾随空白 / 键序都不进摘要。**禁止另写一个「归一化原始字节」的等价实现**：两套等价但不同实现的规则会算出两个不同的 sha，那才是真正的周期性误红（会让人以为声明被篡改）。
2. **门禁自证三原则**（架构 L1300-1310）：① 目标必须显式，且**两件事分别断言**：「解析后的目录」==「期望归档根」，**且确实发生了遍历**（命中文件数 > 0）——只断路径相等时，「路径对但 0 个文件」仍会绿；② 日志必须自证 sha；③ **判据不得窄于契约允许的实现集合**（多合法实现时用集合包含，不用单一等值）。
   > 元规则：**门禁必须能证明「它验的对象」就是「它声称验的对象」**。G-24 空跑（输入=0 条用例）、G-17 词表漂移（输入=空词表）、本次假隔离（输入=错误的树）是同一类——**只约束了输出，没约束输入**。

**批次 xfail 口径**：正常模式允许 `xfailed == EXPECTED_XFAIL`、**不允许 `skipped`**（`skipped` 恒 0；自检用例正常模式**不收集**，机制自选：文件名不带 `test_`（首选）或 `collect_ignore`）；**唯一真源** `tests/expected_xfail.py`（`EXPECTED_XFAIL` 与逐批 `EXPECTED_XFAIL_BY_BATCH`），骨架与门禁一律 import 它，不本地另写；**每批 xfail 条数只降不升（单调不增，B16→B29）**，当前批大于上一批即红——只要 xfail 可以升，任何红都能当天被「豁免」掉，红灯转黄、黄灯没人看，等于又一条「永远绿」路径；每批只要求**该批归属的** xfail 全部转 pass，总量按归属表下降（B16=6 → B17=2 → B19=0），阶段终态 0（**已由主理人 2026-10-23 裁定：归属表 + 只降不升**；当前批大于上一批即红）。`xfail` 与 `skip` 的区别不是形式：前者是**带编号与到期批次的待办**，后者是没有到期日的黑洞。
