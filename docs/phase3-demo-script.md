# 阶段三演示脚本（三个工作台）

> 本文档面向**客户演示**与**实施交付**。演示全程只展示"用户做了什么、系统交付了什么"，
> 不出现任何实现细节与技术名词。

## 1. 这份文档解决什么

一次演示要证明三件事，缺一件就不算演示成功：

1. **三个工作台都能真的跑起来**（不是截图、不是录屏）；
2. **每一单都有"离开界面也成立"的结果物**（文件真的能下载、提交真的存在）；
3. **结果物能核对**：每一单都有一张核查清单，逐项说明"这一项有没有到位"。

## 2. 前置条件

| 项 | 要求 | 怎么确认 |
| --- | --- | --- |
| 运行环境 | 适配层已部署、依赖装好 | `apps/adapter/.venv` 存在 |
| 业务库 | 可连接，且已初始化阶段三的表 | 脚本第 1 步会自检并打印「阶段三的表齐备」 |
| 连接串 | 环境变量 `OA_TEST_DATABASE_URL`（或 `OA_DATABASE_URL`） | 见下方示例 |

```bash
export OA_TEST_DATABASE_URL="postgresql://officeai_app:******@127.0.0.1:55433/officeai"
```

> 缺任何一项，脚本会**直接报错并给出下一步动作**，不会"看起来跑完了其实没跑"。

## 3. 一条命令跑通

```bash
bash scripts/demo_phase3.sh
```

脚本会依次：检查库 → 为演示企业开通能力 → 添加三个工作台 → 各跑一单（过人工确认）
→ 收结果 → 试下载一件产物 → 打印汇总。

**成功的样子**（真实输出，2026-10-22 实跑）：

```
================= 演示结果 =================
租户：tnt_demo_78fb35f5
1. 前端研发工作台（plg_dev_workbench）
   task_id = task_01M5HS2XDF2F9Q0B4X2J4XSK0G
   核查清单 = 4 项；任务状态 = failed；下载验证 = HTTP 200 / 90 字节
2. 内容运营工作台（plg_content_ops）
   task_id = task_01M5HS2ZJKP6EBQD2PW8HGS6HP
   核查清单 = 3 项；任务状态 = completed；下载验证 = HTTP 200 / 90 字节
3. 行政人事工作台（plg_hr_admin）
   task_id = task_01M5HS316WHCZAMGAWJ9P0NTCA
   核查清单 = 4 项；任务状态 = completed；下载验证 = HTTP 200 / 90 字节
============================================
[OK]   三个插件端到端跑通：3 个 task_id 已打印，核查清单项数 4 / 3 / 4（研发 4 / 内容 3 / 人事 4）
```

**判读三条**：

- 三个 `task_id` 各不相同 → 三单真的建成了；
- 核查清单项数是 **4 / 3 / 4** → 与产品说明书里的"交付几样东西"逐字一致；
- 退出码为 **0**。

## 4. 每一步看什么

| 步骤 | 屏幕上会看到 | 这一步在证明什么 |
| --- | --- | --- |
| 1 | 「库连接正常，阶段三的表齐备」 | 演示环境是真的，不是沙盘 |
| 2 | 「已添加并启用（版本 1.0.0）」×3 | 三个工作台都装得上、装完即能用 |
| 3 | 「停在「方案确认后再生成代码，避免返工」→ 确认继续」 | **关键的一步没有替你按下去**：写代码、发内容、发邀约这类动作之前，一定停下来等你确认 |
| 3 | 「核查清单 4 项：已核查 3 / 没有产出 1」 | 好就是好、缺就是缺，不会把"没有产出"说成"已完成" |
| 3 | 「试下载「需求要点」：HTTP 200，90 字节」 | 交付物真的能拿到手 |
| 4 | 汇总表 + 三个 `task_id` | 一单一条记录，事后可追溯 |

## 5. 客户演示话术

### 5.1 开场（30 秒）

> 接下来您会看到三个工作台：**研发、内容、人事**。它们不是三个新系统，
> 而是同一个地方的三套"办事流程"。每一单跑完，系统都会给您一张**核查清单**，
> 逐项告诉您"这次交付了什么、哪一项还没到位"。

### 5.2 研发（2 分钟）

> 我填一句需求、选一个仓库，交给它。它会先把需求拆成要点，再给一份技术方案——
> 到这里它会停下来问我：方案可以吗？**它不会自己往下写代码。**
>
> 我说可以，它才生成代码与用例。写进仓库之前，它**再问我一次**：确认提交到这个仓库吗？
>
> 提交完，清单上四项都能核对：需求要点、代码文件、用例文件、提交记录与合并请求。
> 「提交记录」点开就是仓库里那一次提交——不是系统内部的编号，是仓库里真实存在的那一个。

### 5.3 内容（2 分钟）

> 我给它一个主题、勾两个平台，它先去找素材，再出选题、写稿、排一张发布表。
>
> 这张排期表可以导出，四列：平台、标题、计划时间、状态。表里有几行，就代表要发几篇——
> 不会出现"页面上三篇、导出来两篇"。
>
> 发布前它照例停下来问我。已经接好的平台，会给我一个**发布回执**；
> 还没接的平台，它会老老实实写「待人工发布」，并且把稿件给我下载——
> **不会编一个"已发布"来糊弄我。**

### 5.4 人事（2 分钟）

> 两份简历丢进去，它先写招聘说明，再出一张评分表。
>
> 评分表每人六列，最有价值的是**「风险」**那一列：如果它只写"这个人很好"，
> 这张表就没法用来做决定。所以每一行都必须写清"哪里还不确定、需要面试确认什么"。
>
> 它只给"建议面试"的人准备提纲，每人至少五个问题，每个问题都写着**考察什么**，
> 还带一句**参考追问**——面试官临时想不到问什么的时候有兜底。
>
> 最后是录用通知：**所有金额栏都是空的**。金额只能由人事来填，它不会自己编一个数。

### 5.5 收尾（30 秒）

> 三单跑完，三个编号，三张核查清单。清单里的每一项都能点开。
> 这就是我们要的"离开界面也成立"：**不看这个页面，东西也还在那儿。**

## 6. 怎么算演示成功

| 判据 | 期望 |
| --- | --- |
| 退出码 | 0 |
| `task_id` 个数 | 3 个，互不相同 |
| 核查清单项数 | 研发 4 / 内容 3 / 人事 4 |
| 下载验证 | 每个工作台至少一件产物返回 HTTP 200 且非空 |
| 人工确认点 | 屏幕上出现"停在「…」→ 确认继续"，且**没有**自动跳过 |

## 7. 当前环境会看到什么（如实说明）

演示环境**没有连接客户的邮箱、代码仓库与发布账号**，因此：

- 研发的「提交记录与合并请求」会显示 **没有产出**，任务状态为 **failed**；
- 内容的「发布回执」会显示 **没有产出**（排期表与稿件都正常）；
- 人事的三项全部 **已核查**（公文导出不依赖外部账号）。

这**不是故障**，而是系统在**如实报告**：没有连接的账号，它不会假装提交成功。
正式演示前如需全部通过，请先在"设置 → 办公工具"里完成对应账号的连接，再重跑本脚本。

## 8. 常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报「找不到适配层虚拟环境解释器」 | 依赖没装 | 按提示在 `apps/adapter` 下建虚拟环境并安装 |
| 报「没有数据库连接串」 | 环境变量没设 | `export OA_TEST_DATABASE_URL=...` 后重跑 |
| 报「连不上数据库」 | 库没起 / 口令错 | 确认数据库已启动，端口与口令正确 |
| 报「库里没有阶段三的表」 | 迁移没跑 | 在 `apps/adapter` 下执行 `python -m app.db.migrate --apply` |
| 清单项数与 4 / 3 / 4 不符 | 工作台声明被改过 | 恢复声明文件后重跑（脚本会直接判失败，不会静默通过） |

## 9. 红线

演示过程中**不要**出现：

- 任何模型名、检索技术名、编排工具名；
- 任何权限/令牌/授权之类的工程词汇（要说"能不能让它做这件事"）；
- 任何四位错误码、堆栈、"重试一下就好了"这类说法。

统一说法：**"它停下来了，请您确认" / "这一项还没有到位，可以这样补"**。
